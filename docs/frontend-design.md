## 1. 不变的设计原则

- **2026-11-13：参考设计优先，组件随真实需求演进。** 先核对优秀产品如何组织工作流/展示，再列`web/src/ui/`及用例哪些保留、哪些改造/替换组合。旧UI-1不得阻止必要重构，Ant官网也不能代替成熟应用的设计依据。改进应统一沉淀、回归共享消费者，不各页私造主题或业务状态机。完整当前规则见[开发规范总览](development-standards.md)；已实现工程能力保留，先纠正被否定的工作台布局再继续扩展。

- **2026-11-12最新用户纠正适用于所有功能：先实际参考、后设计实施。** 用户再次强调 **Cyber与ARTEX优先**，首要入口为 <https://cyber.chainreactors.cn/tasks>；既看功能组织、操作流程和字段，也看实际视觉展示，不能只取字号/密度后自行猜交互。无对应功能或无法观察时，再查其他成熟项目的同类界面/官方材料，标明实际观察、源码核对与未知，任务包记录沿用点及必要差异；重大差异先沟通。具体证据及只读边界见 [界面参考](ui-reference.md)。技术测试通过不是设计依据或用户认可。
- **新增仅待设计**：[方向执行记录与任务内对话](task-interaction-backlog.md)。按方向查看实际下发说明、调用/工具输入输出和结果；任务内询问状态、提出受控调整。参考ARTEX已有执行流/对话组织，具体布局尚未冻结，不先造聊天壳或假日志。日志原文遵守记录开关，查询不启动研究，调整必须有真实操作回执；不替代既定流量、发现或探索图谱。
- 配置保存就是更新，不给用户增加内部revision/v1/v2或秘密keep/replace/clear操作；API key采用必填密码字段，已保存值不回显，改其他字段不强迫重填。此要求也用于审视其他功能，不仅模型页；不能仅删标签后仍要求用户理解原有机制。必要并发保护、在途一致性及证据来源保真另论，不把它们包装成产品版本管理；当前相关后端事实不因此自动改变。

- React + TypeScript + Vite + 官方 `antd` / `@ant-design/icons`；Vue 仅原型，不继承其布局、CSS、导航，不用相似手写样式冒充官方组件。
- 用户先看问题、依据、下一步与需要处理的风险，不看容器拓扑、全量聊天或假 KPI。没有真实能力时不设发现数量、统计首页或完成率。
- 旧14px紧凑基线是实现起点，不是2026-11-13整改的设计上限；按实际参考、清楚层级和阅读效率统一调整排版/密度/内容宽度，不把正文横铺整屏或仅调字体称作设计完成。保留必要状态/前提，去冗余，不以Tooltip承载关键操作或正文。参考与只读边界见[界面参考](ui-reference.md)。
- 不添加常驻小字辅助说明、解释段或常驻告警，也不靠放大字号/换位置保留；真实任务内容、必要操作和授权输入保留，错误/必填校验在实际触发处显示。未知效果仍按真实状态展示，能力事实留开发/API文档，不因此改变授权/执行行为。
- G0 不新增前端依赖，不切换 React 入口；正式迁移时核验兼容和许可证，不默认引入 Pro/Ant Design X/图表库。

## 2. 信息架构与分片开放

首个新语义工作面顶层为 **项目 / 流量**。方向是研究中心；场景 Profile 是项目/任务上下文，不再按每个场景造一个独立应用。发现、报告与 SDL 在对应后端片完成后逐步开放，不提前放可点击占位导航。

| 目标页面/路由示意 | 职责 | 开放条件 |
|---|---|---|
| `/login`、`/projects`、`/projects/new` | 登录、选择/创建明确授权项目 | F1/C1；当前仍只有令牌和 origins，不伪造身份体系 |
| `/projects/:missionId` | 场景、目标、授权、研究方向与材料 | 场景字段未实现时只显示真实字段 |
| `/projects/:missionId/threads/:threadId` | 问题、依据、下一步、证据与真实研究控制 | F2；协作视图随 R2 能力开放 |
| `/traffic`、`/traffic/requests/:requestId` | 类 Burp 流量记录面板、请求/响应查看与复制；待放行、拒绝/自动放行和未知核对 | G1/F3；原生工具覆盖需 E1，不是简单给旧 Action 路由改名 |
| 项目内探索图谱 | 可追溯的探索活动、验证、证据与发现关系，可定位具体流量 | F2 与结构化来源关系；不以聊天记录或模型补写的关系冒充事实 |
| 项目内 `findings` 及详情 | 简洁的描述/复现步骤/修复建议，关联具体流量；逐漏洞发现时间线 | V1/F4 与稳定证据/事件关联 |
| 项目内 `reports` 及版本详情 | 草稿、引用、导出、发布版本 | V2/F4 |
| 漏洞内复测及报告记录 | 发起单漏洞复测、查看每次结论与新证据/报告，不覆盖原发现 | 独立复测后端契约，见成果文档 |
| 报告/发现/复测中的外部任务与投递记录 | 外部任务来源、映射、回执、失败/未知与核对 | S1 或独立复测连接器；不单独造未实现的运营中心 |

上表混合目标与分片：当前 React 已实现 `/login`、`/projects`、`/projects/new` 和项目/方向只读路由，研究控制未开放；其余仍是示意，不是已支持 API/页面。现有 `/actions` 原型按 G0 事实显示“已放行/待审批”等状态：新 HTTP pending 来自破坏信号，历史 pending 可能来自旧全审批，不能把全部 pending 伪装成“危险请求”，也不能把全部 approved 标为“人工批准”。项目内列表和跨项目列表共用详情组件，不复制业务决定逻辑；项目内使用就地检查器查看证据，保持阅读上下文；新建/配置/补资料用居中Modal，不以Drawer作为默认方案，不叠加弹窗。

URL 仅存对象 ID、页签与非秘密筛选，不存令牌、请求头/正文或草稿。跨项目关联须核对归属，不能拼接其他项目材料。

正式入口当前使用路由驱动创建Modal：`/projects/new`仍可深链；从列表或工作面打开时来源DOM保持挂载，关闭返回来源并归还焦点，历史前后退与401重新登录保留内存草稿/提交核对状态，显式退出清空。history只记录经过验证的来源路径及后退标记，不保存秘密或提交键。创建期间不叠加证据检查器焦点陷阱；共享组件不接管业务提交。

## 3. 关键页面与主操作

### P1：任务创建、授权与开始探索（J1）

登录只有名称、令牌与进入；用受保护接口验证，不伪造账户登录。项目列表是名称、目标、创建时间与真实模式字段，不编造更新时间/漏洞数。

首版 Web/API 创建入口按用户要求组织为两个主要输入：**目标／已知信息**、**希望达到的目标**。用户不必填写研究计划或手工创建方向；点击 **开始探索** 后自动建立初始方向并推进。建议名称选填或自动生成，预算等高级配置按需展开，细节仍待确认。正式前端入口已实现并通过本地浏览器交互验收、尚未切换服务；后端首轮已提供 `POST /api/explorations` 与提交核对，名称自动取目标摘要、使用现有部署步数上限，具体契约见 [api](api.md)。完整启动建议及 ARTEX 参考见 [research-start-and-prompts](research-start-and-prompts.md)。

实际授权在同一创建界面明确展示规范化范围；可信用户未给出可执行范围时补齐后再开始，不让模型从背景引用或目标响应扩大权限。未实现 Profile 和资源授权前只提供现有 HTTP origins 契约，不做可选择但无实际行为的“CTF/代码审计”选项。背景 `origin` 与 `allowed_origins` 明确分开。登录态/多身份如何提供仍待确认。

**当前兼容行为**：旧创建 Mission 只保存、不调用模型/目标；旧 Thread 需另行创建和启用。新独立后端“开始探索”已将保存与显式启动合并为一个事务，不是偷偷改变旧创建接口；创建成功、已接收启动与实际运行分别按服务端事实反馈，响应失联先核对，不重复建任务。若保留“仅保存”，它仍不启动研究。当前授权创建后只读，未来范围修改需版本及受影响工作说明。

### P2：研究工作面（J2、J4、J5）

区域顺序：方向名称/状态 → 问题与下一步 → 当前阻塞/主操作 → 依据与证据 → 相关工作/过程 → 次级控制。

- 主操作是启用/继续研究、查看材料或处理相关阻塞，而不是默认“提出动作等审批”。人工仍可记录观察、提出受控工具任务。
- 尚未实现的 Profile 不提供假选项，模型未配置时不能启用研究；“已配置”不标为“连接正常”。已有工具与联网默认可用，不再提供逐场景工具名单或逐命令审批入口；缺失工具如实报错，不伪造执行结果。
- 模型观察、人工记录、工具回执分开；摘要不覆盖原件，不伪造 Thread.summary。
- G0 仅 pending 时显示待决定请求与原因，不让自动 approved 继续显示“等待批准研究计划”；历史 pending 不自动释放。只说明实际被阻塞的工作，不显示整个项目停工。
- 协作实现后才展示来源问题、分工范围、输入证据、结果交回与失败；worker 数量不作为“专家数量”。没有业务冲突检查前不声称可安全任意并行。
- 步数/费用只显示服务端真实事实；现有只有方向累计步数，不画完成率、不伪造剩余费用。不提供复制方向清零预算的快捷操作。

### P3：流量与待放行请求（J3）

用户已明确要求类似 Burp 的流量记录面板，能看请求与响应，而不只是审批列表。建议以 **记录 / 待放行 / 待核对** 组织工作面；布局和筛选细节尚待确认。完整契约落地后区分策略自动放行、人工放行、策略拒绝、执行结果；G0 仍使用 Action，不能从 approved 单独推断放行来源，不把全部请求都堆进审批队列。

记录面板建议使用可筛选的请求列表与请求/响应详情，桌面并列查看，小屏切换但不缩小字体。按实际契约显示时间、方法、URL、状态和来源，可复制请求、响应及已保存字节。文本报文若由捕获字段重建，须明确为重建展示而非线上原始报文；格式化视图不改原件，捕获截断和预览限制分别标记。未发送/待审/拒绝记录无目标响应，不伪造响应包。原件与脱敏内容的复制需明确选择，复制不触发执行。记录覆盖范围必须随实际适配器声明，原生工具未接入前不声称捕获所有流量；类 Burp 面板不自动包含完整代理、Repeater、扫描器或全协议能力。

待放行详情按顺序呈现：

1. 所属项目、方向/工具及验证目的。
2. 实际请求的方法、规范化 URL、请求头、正文与身份上下文；不可变引用/指纹可展开。
3. 命中策略与拦截理由、范围、有效性/过期情况。
4. 当前可用决定与真实执行结果。

只对 review 项显示 **放行此请求 / 拒绝**。deny 项没有越过授权的“强制批准”；allow 项无需用户点一次同意。修改参数属于新请求，重新评估，不在审批表单中边改边批。过期或会话/规则变化后不盲目沿用决定；批准不声称已经发送，暂停时说明仍等待调度。

默认不做批量放行或一键重放。放行按钮就是一次明确决定，不叠同义确认框。关键材料关联读取失败时不能放行；必要参数可完整阅读。秘密值默认遮蔽、按需本地显式查看，关闭详情复位，不写 URL/日志/遥测；脱敏不修改原件/指纹，也不承诺识别全部秘密。

策略拒绝/挂起显示为控制面结果，不能伪造目标状态码。一个工具产生多个请求时能定位各自状态，不把某次放行解释成整个工具无限获准。

### P4：证据、未知与接续（J5）

执行状态和来源 → 保存字节/代码位置 → 捕获限制 → 实际元数据。动态请求结构化捕获不叫线上原始报文；静态位置绑定仓库 commit；版本能力未实现时不伪造引用字段。

- 文本/十六进制/Base64 只是同一字节的不同视图，解码失败保留原字节。
- 捕获截断与界面预览分开。当前整体 truncated 不能显示成每流精确缺失长度。
- 下载标为“下载已保存字节”；没有原件不造附件，不能拿截图替代原件。
- 目标响应、代码、终端输出与报告均作为不可信内容，禁止脚本/HTML 自动执行和外部资源自动加载。

未知效果仍是原请求、已有材料、核对说明和 **保存核对记录**。旧 unknown 历史不改成成功，不自动重放。无法安全接续时只补充观察，不能把 resolve 当普通记事。当前 resolve 关闭 auto_run，ready 可人工继续，paused 需明确恢复；新请求模型的对应行为在 G1 契约中冻结。

### P5：编号发现与报告（J6，后续）

发现列表优先编号、标题、验证状态、严重度依据与影响对象；**有编号不标为已确认**。用户已要求漏洞详情简洁，主正文固定为三个部分：

1. **漏洞描述**：几句话说明原理与危害，不堆长篇通用背景。
2. **复现步骤**：按顺序简短说明实际操作，保留必需的身份/环境前提；步骤关联具体流量，能就近查看和直接复制请求/响应，不用模型编造的示例报文替代证据。
3. **修复建议**：直接给出与问题相关、可执行的修复建议。

编号、标题与真实状态放在精简页头；支持/反证、发现时间线、图谱关联、版本与复测历史通过独立页签或按需展开查看，不增加主正文的大段说明。流量查看复用同一组件和稳定引用，不在详情中另存一份易漂移的请求副本。后续其他场景按真实位置/证据类型扩展，不伪造 Web 流量。

报告工作面提供模板与范围、生成草稿、证据引用核对、版本阅读和导出。模型生成失败保留已有版本；缺证明确标记，不给“自动补齐事实”入口。生成、正式发布、SDL 投递分别显示，不把一个“成功”覆盖三个状态。

SDL 区域仅在连接器配置且获授权后开放，显示目标、远端 ID、发布版本与回执。结果未知优先核对，不提供会重复创建漏洞的盲目“再试一次”。具体内容见 [findings-and-reporting](findings-and-reporting.md)。

### P6：探索图谱与逐漏洞时间线

用户已明确要求探索图谱和每个漏洞的发现时间线，两者不是可随意用聊天窗口替代的过程列表。建议图谱按已保存的研究活动、验证动作、流量/观察证据和发现组织关系，支持定位相关活动及具体流量；默认聚焦相关子图，大规模布局/聚合与组件另行选型。只展示已保存的结构化关系，缺少来源时保留未知，不由模型补画因果链。

漏洞时间线展示与该漏洞有关的实际活动和证据产生顺序，可查看发现、验证、结论变化及各次复测；它不是全项目日志，也不是模型事后编写的发现故事。图谱、时间线、流量和详情共用身份/证据引用，关系跳转要核对项目归属；未参与首次发现的复测不能倒插成最初发现依据。

过程用于解释当前状态，不替代权威对象，不画固定扫描阶段进度条。当前事件 API 为 `after` 后最早最多200条，按末条 ID 接续和去重；不是最新200条，不从自然语言 message 猜 action_id。现有事件没有完整的流量/发现/复测关联，不能直接冒充已实现图谱或逐漏洞时间线。

### P7：复测与复测报告

每个漏洞提供复测入口及历史记录入口；发起复测后显示本次真实状态，完成后可查看独立报告、新请求/响应证据及结论。历次报告保留，不覆盖原漏洞描述与最初证据。正文仍遵守 P5 的三个部分，不把整个复测运行日志铺在漏洞详情中。

复测执行状态、漏洞验证结论与外部结果投递状态分别呈现；无法登录/目标不可达/证据不足不能显示为“已修复”。外部来源任务可查看其关联，投递失败只重试结果传输，不将“重新投递”做成重新测试按钮。接口协议、结论枚举、权限与具体交互在实施前冻结，参见 [findings-and-reporting](findings-and-reporting.md)。

## 4. 当前兼容语义与新目标必须分开

当前原型与正式迁移必须遵守 G0/旧数据的真实限制，不能通过文案升级成新能力：

| 当前后端事实 | 旧数据/兼容界面要求 |
|---|---|
| 新命令默认 approved；HTTP 命中明确破坏信号才 pending | 不显示每个命令都需审批；`request-signals-v1` 是启发式，未命中不代表安全，未知不一律待审 |
| 历史 pending 不重评或自动放行 | 如实显示待审批，不自动归类为新策略命中的危险请求 |
| approved 可能来自策略或人工，仍未执行 | 优先标“已放行”；暂停下不派发，当前无撤销 approved 接口 |
| 策略理由与哈希同事务保存，人工 decision_reason 可覆盖 | 初始理由还在 action.proposed 事件；不伪造独立策略记录/人工身份字段 |
| 工具默认 bridge，可设 none；直连未拦截或强制 origins | 在相关网络/授权操作处说明覆盖范围，不宣称所有工具流量已受控 |
| pause 不取消在途 | 显示请求暂停后续派发；auto_run=false 不能代替 pause_requested |
| resume 不启用模型，但可放行原 approved | 恢复前列出将允许执行的旧动作，不用“继续”隐藏影响 |
| blocked 不是全部动作的停止开关 | 联合动作/在途/暂停事实，不只看 Thread.status |
| unknown 未核对不可接续 | 不重放；核对后历史仍 unknown，按 ready/paused 显示 |
| 步数用尽或 concluded | 不清零、不隐式重开、不显示“已证明安全” |

G1 的完整流量界面仍需独立读取请求、策略和放行记录；G0 没有一工具多请求模型或完整业务风险分类，不能从 Action.status 推断这些新增字段。具体迁移和新增 API 先冻结再实施，见 [api](api.md)。

## 5. 写入、草稿与会话可靠性

- 首次加载使用骨架；读取失败保留旧内容并就地标未更新，不渲染为空列表。
- 400 定位字段；401 遮蔽敏感材料并重新认证；404 不无限轮询；409 重读对象；503 就地显示能力不可用。不自动重发原写操作。
- 浏览器写入超时/断网表示“提交结果待核对”，不是请求执行 unknown。C1 实现后按同一幂等键核对回执；用户明确重试仍复用同键，不能生成新键重复创建。
- 不用乐观更新伪造已批准、已发送、已确认、已发布或已同步；写后以回执和重读事实为准。
- 令牌、草稿、敏感证据默认只留内存；轮询、应用内切换和临时重认证不吞草稿/焦点。离页/刷新有未保存确认，不承诺崩溃后恢复；退出清空。浏览器取消等待不等于取消服务端写入或目标请求。

## 6. 视觉、组件与工程分层

- **2026-11-11最新要求：以实际最大化Web浏览器可用窗口为主，优先布局舒适与密度。** 展示取消固定viewport，记录真实窗口尺寸；另以1440×900与1920×1080检查浅暗布局，查看整体比例、宽度、留白、对齐与层级。功能通过、字号检查不能代替视觉验收，390px移动端保基本操作。
- 桌面利用可用宽度，不强制统一1200px窄列；按功能调整分栏/断点，真实内容少时允许自然留白。减少重复容器/整行操作，短状态/时间/操作同行；不伪造统计填空。
- 标题/控件/表面/动效以最新UI-1为准；正文、状态、时间、placeholder、Tooltip与错误14px，标题16/20/22px。桌面控件36px/紧凑32px，触屏主要按钮至少40px，保留键盘和焦点。
- 统一ConfigProvider中文和浅暗token；状态有文字，不依赖颜色。共享主题单一来源，必要Ant6表面覆盖有针对性测试。
- 每个局部上下文一个主操作；长正文局部换行/滚动。任务Modal串行切换，正反Tab循环、关闭返回来源焦点，普通Enter不误放行请求。
- Form/Input/Button负责输入，Table/List/Tabs组织对象，Descriptions/就地检查器查看详情，Modal承载新建与配置；Skeleton/Empty/Alert/Result反馈真实状态。不再包装整套基础组件，不用静态消息丢失主题。
- 应用层：路由、鉴权、主题、会话；业务层：projects/threads/traffic/evidence，后续 findings/reports；接口层：类型、过期响应、提交核对。业务状态始终来自服务端。
- 当前 Snapshot/列表无分页，客户端筛选仅在完整集合上成立；不能静默截断再显示全量计数。

## 7. 迁移与验收

一套正式入口；新语义链路验收前保留可恢复旧产物，以隔离预览验证。不清空旧代码、不长期双前端、不同时启动两个控制面。新增依赖、实际切换和重启均按当轮授权。

分片门槛：

1. “仅保存”与旧创建 API 不调用模型/目标；目标入口的“开始探索”可可靠保存并显式启动，无需手工建方向；响应失联不重复建任务。授权与 profile 不混同，未支持模式无假入口。
2. 策略允许请求自动通过，review/deny 发送前零泄漏；探索不逐步审批；依赖等待与独立工作可区分。
3. 暂停/恢复/旧 approved/unknown/预算语义真实；写回执丢失可核对，不重放外部请求。
4. 编号、验证、报告、SDL 只随真实能力开放；草稿不冒充确认或发布，投递未知不重复创建。
5. 最大化实窗及1440/1920/390px布局、14px正文基线、键盘/焦点、401/404/409/503/断线/空态及过期响应按变更范围覆盖；工具仅达500px时不能称390px通过。
6. 原件/预览/截断/下载一致，不可信内容不执行，秘密不落浏览器持久存储。
7. 真实 API 与本项目受控 fixture 验证，类型检查与构建；控制台/网络错误逐条记录。未验证模型效果不包装成自主研究质量通过。
