# 路线

目标：首版在本地靶场跑通完整链（[product.md §6](product.md#6-首版验收基准)）。每片是一条完整用户链，前后端一起交付，完成即提交，进入下一片。

| 片 | 用户可见结果 | 负责 | 前置 |
|---|---|---|---|
| R1 真实验证链 | 对候选发起验证，真实模型取得新证据并给出判读，页面可读 | 主跑 + Kimi/GLM 修问题 | 用户确认模型/靶场使用 |
| R2 执行复盘 | 按方向/会话看下发任务、模型与工具交互、证据与候选产出 | GLM（必要时 Kimi 补接口） | 先读 Cyber 原生会话/Workflow 与 ARTEX 会话页 |
| R3 报告 | 选定候选（固定修订+验证结果）→ 模型生成报告草稿 → 目录+限宽正文阅读 → Markdown/JSON 导出 | Kimi 后端 + GLM 前端 | 先核 Cyber 原生报告会话（`startReportSession` 会触发 Run）能否直接复用 |
| R4 复测 | 漏洞内发起复测，独立结论与新证据，历次可回看 | Kimi + GLM | 复用验证执行路径 |
| R5 首版验收 | 靶场完整链一次跑通，记录问题 | 主 | R1–R4 |
| 之后 | 用量/原文记录、资料库与 Skill、测试安全提示词、任务内对话、图谱/时间线 | 按需排序 | 每项先核 Cyber 原生已有能力 |

延期（首版不做）：请求级风险审批、全工具强制出口、外部 SDL/复测平台对接、多用户、部署。

## 每片的固定步骤

1. 主：读相关代码与参考，写 20–40 行任务包（路径、契约、可写文件、验证、停止点）。
2. 执行者实现并交回 `result.md`。
3. 主：读 diff、跑定向测试/构建、浏览器亲自走一遍用户链（含展开态与窄屏）。
4. 主：修正一次到位后 commit，改写 STATUS“当前/下一步”，接下一片。
