## 1. 产品方向与本轮终点

完整目标是可扩展的授权安全研究平台：漏洞挖掘、代码审计、CTF、内部攻防演练共用内核，按场景 Profile 和适配器扩展；形成稳定编号的发现、证据驱动报告并对接内部 SDL。不强制黑板，不固定多层专家角色。

审批只针对实际出站请求的风险拦截；内部推理、探索意图和每个工具调用不默认逐一审批。旧路线中的“所有动作人工批准”及围绕它直接推进 F3 的建议已撤回。

用户最新确认：**首版聚焦 Web/API 漏洞挖掘**，不同时展开代码审计、CTF 和内部演练。明确要做的功能另包括类 Burp 请求/响应流量面板、探索图谱、逐漏洞发现时间线、只以描述/复现步骤/修复建议为主正文且关联可复制流量的漏洞详情，以及逐漏洞复测/报告和外部平台双向复测任务对接；不要求第一步全部实现。具体交互、接口、分片次序与组件仍待沟通确定。

任务入口进一步明确为“目标／已知信息”和“希望达到的目标”两个主要输入，点击“开始探索”后自动建立方向并推进，不要求用户先拆研究计划。可靠保存/启动与现有 API 的区别、ARTEX 提示词参考见 [research-start-and-prompts](research-start-and-prompts.md)。

此前选择的研究证据闭环保留为首个可验收切片；发现/报告/复测属于明确产品目标，分阶段交付，不再把它们描述为产品无关能力。首轮已获明确开工授权并完成后端子片；下文 G0 保留为历史实现记录，其他路线任务不因此全部获准。

历史设计轮次交付 vision V2、architecture A3 与候选调研，随后 G0 实现了新动作策略分流、默认 bridge/可选 none、共享 runtime 配方及原型语义同步；不把轻量启发式写成完整 G1，新 runtime 镜像未构建或运行。其后已完成产品需求与 ARTEX 研究，并在明确授权后实施可靠启动后端首轮；未替换运行时。

## 4. 可独立交接的任务包（尚未派发）

### P0：轮子评估与边界冻结

- **入口**：components、architecture、api 第5–7节、findings-and-reporting；domain 与当前执行链。
- **产物**：先评估 Eino；ADK Go 备选；选一种出口方案与一个场景工具，不预定全部引入。记录许可证、运行依赖、状态归属、替换成本、采用/不采用理由及未核实项。
- **关键实验（另行授权）**：有限工具调用、中断后恢复、待审不空转、已经发送的外部请求不被框架重放；只用隔离 fixture/测试模型，真实模型与效果实验另行授权。
- **冻结内容**：Tool action/Outbound request/Policy decision 关系、旧 Action 兼容与迁移、批准有效性、profile 与权限交集、证据引用。
- **停止**：文档可以独立交付；不因候选成熟就安装，不自动开展 G1/R1。

### C1：持久基础与控制面提交核对

- **目标**：显示真实暂停/步数事实，独立定位旧动作，写回执丢失可核对；新增持久结构安全升级。
- **归属**：一个后端负责人拥有 domain/store/httpapi、迁移和专项测试；主 Agent 拥有共享文档。公共文件不多人同时写。
- **契约**：保留 api 的当前语义；幂等键作用域、同键冲突、回执保留、旧客户端兼容先冻结。未来请求/成果的写入同样遵循，不意味着本片创建全部新实体。
- **验收**：同键并发/响应丢失/重启/事务回滚；旧成功回执与当前对象分开；升级保全证据与旧批准记录；不自动重派发。

### G1：最小请求级流量控制

- **目标**：在 G0 上明确策略覆盖、独立请求/放行记录及恢复语义；命中需人工判断的请求发送前等待，越界请求拒绝，不把所有未知请求一律待审，也不恢复逐命令审批。
- **范围**：先平台代发 HTTP，不接通用浏览器/MITM；工具默认 bridge 已是 G0 行为，直连缺口由 E1 补齐。历史 pending 不自动放行，旧 Action 迁移与 UI 兼容必须明确。
- **验收**：策略明确允许的请求正常发送；GET 删除语义、POST/RPC 危险内容进入拦截；拒绝/待审零发送；参数/身份/策略变化重新评估；等待不调用模型，独立工作可继续；unknown 不重放。规则效果只在指定 fixture 上成立，不宣称识别所有业务风险。
- **停止**：执行器、持久门禁、最小真实工作面与恢复验收完成即交回，不自动扩展全协议工具。

### R1/R2：通用研究与按需协作

- **目标**：首版先实现 Web/API 的自动启动、证据引用与受控上下文；后续再用第二种场景检验同一内核。共享相关证据而非全量聊天；必要时有限派生任务并消费结果，不把多 Agent 或第二场景作为首版门槛。
- **契约**：Profile/工具/材料版本、项目与任务授权交集、证据来源、父子/依赖引用、总预算及资源冲突；不是 profile 自己生成无限权限。
- **验收**：模式切换不扩大范围；跨项目材料不可见；新方向消费旧证据；分工预算不倍增；同业务状态不并行写；失败保留材料和未决问题。研究质量评测与工程 fixture 分开。

### V1/V2/S1：成果与交付

- **目标**：编号稳定、候选与确认分开，模型自动生成有引用的报告，并通过单个真实协议交付 SDL。
- **归属**：领域/持久层与前端按冻结契约独立交接；报告渲染器与连接器各有单一负责人，不让框架/外部 SDL 成为第二事实权威。
- **验收**：并发编号、重复发现合并、证据版本/缺证标记、敏感信息、渲染隔离；远端成功但回执丢失不重复建漏洞；重试交付不重新执行目标动作。
- **停止**：V1、V2、S1 各可独立交付；无内部 SDL 契约时只停在本地模型/导出，不猜接口。

## 5. 开发协作、全局门槛与效果评测

主 Agent 维护范围、接口、单一文件归属、整合与 STATUS；最多额外两个会话，优先一个，每个只完成一个短轮次后交回退出，执行会话不再委派。主/执行均用可见交互终端，不设整轮强制超时。模型分工以AGENTS顶部最新路由为准。具体调度见[开发会话约定](development-sessions.md)。**开发用主/子 Agent 不代表产品运行时已经具备多 Agent。**

每包交回修改路径、决定、验证/失败/未验证、在途任务与停止点，不复制秘密、大量日志或让用户管理各 Agent 上下文。共享 domain、路由、主题、API 客户端、依赖 lock 只有一个写入负责人。

全局门槛：

1. 先复用调研再实现；新增依赖锁定版本、记录引擎/规则/模板各自许可证及来源。
2. 目标与现状分开，不能用文档、mock、框架宣传或工具成功代替发现有效性。
3. 不扩大授权、不删除未知历史、不重放可能已发送请求、不因派生/恢复清零总预算。
4. 功能有完整用户行为终点；正式页面复用本项目组件库、真实API、14px正文基线，无占位/演示发现或假统计。
5. 只按当轮授权操作模型、目标、SDL、服务、依赖、测试库与 Git；不默认全仓测试套餐。
6. 分场景建立受控评测集：Web/API 有可验证业务副作用与反证；代码审计固定 commit 与已知缺陷/良性样本；CTF 用获准靶场规则；演练验证授权/停止条件。比较有效发现、误报/漏报、重复劳动、人工干预与成本，不能把找到 flag 等同于生产漏洞能力。
