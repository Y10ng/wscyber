# 路线

**长期目标：企业内部自动化渗透 Harness。** 资产登记一次 → 按周期自动下发渗透任务 → 只把经独立验证的漏洞精简推送到 SDL／企业微信（附 HTTP 原件截图）→ 平台保留完整记录、审计可追查 → 危险操作被审批拦截 → 连接器与能力可扩展。不追求一步到位，每片仍是一条完整用户链，前后端一起交付。

## 阶段与片

| 阶段 | 片 | 用户可见结果 | 依据 / 复用 |
|---|---|---|---|
| A 首版收尾 | R1 真实链 | 真实模型在靶场跑通 建任务→验证→报告→复测，按问题清单修复 | 进行中 |
| | 用量 | 每任务/每日 tokens；周期任务的预算依据 | 先核 Cyber 原生 usage |
| B 无人值守的安全底座 | B1 测试策略 + 审批拦截 | 任务级“测试策略”开关：范围（仅授权 origins〔默认〕/ 不限制）、审批（关 / 仅高危〔默认〕/ 全部人工）；建任务时 AI 从描述识别 origins 作建议、用户确认。审批开启时危险操作（破坏性 HTTP 方法/接口、删除数据、高危命令）暂停等人批，超时＝拒绝，决定入审计 | 上游 `exts/guardrail`（safe/auto、Pending/Resolve、超时）+ 原生 GuardrailToggle；本项目补 Web/API 规则与按资产策略 |

| | B3 审计视图 | 谁在何时启动/批准/推送/改配置，可筛可查 | 原生 AOP 事件 + 业务表 |
| C 资产与周期任务 | C1 资产登记 | 资产＝名称、负责人、环境、授权 origins、已知信息、测试账号（密钥存储）、禁止行为、审批策略、SDL 映射；从资产一键建任务 | 现有任务模型扩展 |
| | C2 计划任务 | 资产/资产组配 cron；到点自动：探索 → 候选自动验证 → 已知漏洞自动复测；并发与预算上限；运行历史 | Hub 内调度器（上游 `agent/cron.go` 解析） |
| | C3 资产漏洞库 | 跨轮次去重：新发现 / 仍存在 / 已修复；候选→漏洞的归并有人可改 | 复用验证、复测 |
| D 对外推送 | D1 证据图片 | 由已存 HTTP 原件确定性渲染 BP 风格请求/响应图（关键行高亮）；需要时附浏览器截图 | 不让模型画图；上游 `tools/playwright` 截图 |
| | D2 企业微信 | 群机器人：新确认漏洞的精简通知（标题、等级、资产、一句话危害、关键复现步骤、图片、平台链接） | 只推验证“支持”的；可设人工确认后再推 |
| | D3 SDL 对接 | 通用出站连接器（模板化 JSON、重试、投递记录）→ 按 SDL 接口做适配；之后 SDL 状态回传触发复测 | **需 SDL 接口文档**，无协议不猜 |
| E 扩展 | 资料库/Skill、外部 API 触发任务、连接器插件化 | 按需 | 优先原生 Skill/MCP |

降级或合并：测试安全提示词并入资产“禁止行为”（软约束）+ B1（硬拦截）；任务内对话直接用原生 Chat，不单独开发；探索图谱、模型原文记录排到 E 之后。

## 推荐顺序与理由

A → B1 → C1 → C2/C3 → D1/D2 → B2 → D3 → E。

- 周期任务只有在单次结果可信时才有价值，所以先收尾 A；推送只推经独立验证的漏洞，压误报。
- 限制都做成可选的测试策略，默认开启基础限制（仅授权 origins + 高危审批）；纯测试环境、要求最深挖掘的任务可由用户显式关闭。B1 是无人值守的前提（默认策略下危险操作需有人能批）；B2 在正式周期化上线前补齐，此前“仅授权 origins”的周期任务只开放 `webapi_http` 与浏览器类受控工具。
- D3 依赖外部接口文档，先做企业微信与通用连接器。

## 到对应阶段需要用户提供

- C1：测试环境账号的存放方式（平台加密存储即可，还是对接内部密钥服务）。
- D2：企业微信群机器人 webhook（或应用消息）；平台对推送接收人可访问的地址（链接回平台详情）。
- D3：SDL 平台接口文档与测试环境。
- 若审批要由别人在手机上批：需内网部署地址与账号体系（目前单机、单 key）。

## 每片的固定步骤

1. 主：读相关代码与参考，写 20–40 行任务包（路径、契约、可写文件、验证、停止点）。
2. 执行者实现并交回 `result.md`。
3. 主：读 diff、跑定向测试/构建、浏览器亲自走一遍用户链（含展开态与窄屏）。
4. 主：修正一次到位后 commit，改写 STATUS“当前/下一步”，接下一片。
