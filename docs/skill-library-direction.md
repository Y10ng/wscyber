# 辅助型 Skill 库：方向调整与实现影响

更新：2026-11-12。**原入口已转达用户选择“区分Skill与普通资料”：共用一个库，只有显式设为可供Agent使用的Skill参与自动发现/按需加载，普通资料仍显式提供给任务，旧条目不自动转换。** **S1现已实现并完成受控本机验证与正式React展示**，现行契约/API见[automatic-skills.md](automatic-skills.md)、[api.md](api.md)，产物与验证范围见[STATUS §0.24](STATUS.md#024-s1辅助skill已实现并完成本机展示2026-11-12)。下文保留交权前的影响核对与建议作为历史，表中“尚无/待冻结”只描述当时状态，不覆盖S1当前实现。旧代码、历史材料、失败证据和固定预览保留。

## 1. 新方向与暂停范围

- 自主研究循环根据问题、状态和探索方向决定是否使用Skill；Skill提供辅助方法，不规定研究流程，不成为必须完成的流水线或覆盖清单。
- 用户可以维护多个Skill；默认不要求每个任务创建前逐个勾选才能使用。
- 项目应能看到实际使用过哪些Skill及相应记录。目录曝光、模型声称使用、成功加载和进入模型调用是不同事实，不能混为一个计数。
- 已暂停固化旧C1的“必须创建时手工选定，运行时仅使用这些固定资料”作为最终产品路径。现有`materials`接口和测试仍是当前代码事实，不能改写历史输入/回执或谎称新方向已实现。
- 文件夹/文本管理、单文件导入、严格输入、草稿/401/迟到保护、CAS与只读核对、附加安全清单不与新方向冲突，可保留并完成已在做的基础验证。

## 3. 交权前的最小运行契约建议（历史，已由S1取代）

### 发现、加载与继续研究

1. 复用既有薄循环。新增只读的Skill发现/加载研究活动，处理结果持久化后，由下一正常决策轮消费；不引入新Agent框架、独立Skill调度器或固定“先选Skill再推理”的强制双调用。
2. 目录仅提供有界名称、简述/适用信息和来源身份，支持分页/查询；目录内容同样属于不可信研究数据。不是一次把2000份说明或全部正文塞进上下文，也不偷偷由程序按关键词替模型决定唯一Skill。
3. 加载由Agent根据当前状态/方向提出具体Skill身份及目的。平台复核可用范围、内容、大小和预算，再固定该次来源、正文/hash。后续库修改或删除不改已加载历史。
4. 已看到的目录条目若随后变化/删除，应得到可辨认的失效/失败结果，不能悄悄换一版正文；可由后续正常研究决策重新发现或改选，不无限自动重试。
5. 加载结果绑定项目和方向。模型上下文只消费当前需要的有界结果，历史完整原件仍可追溯；不能把项目全部历史加载在每轮重装。复用已固定结果与明确再次加载是不同事实。
6. 目录/加载也消耗既有研究步数和上下文预算，不形成不受限的内层循环。成功/失败/空结果均应真实反馈；无Skill可用时正常研究仍可继续。数据库失效时保留现有fail-stop原则，不为了绕过记录而偷偷继续发送。
7. 初期仍仅把Skill当文本方法：不执行scripts、不安装依赖、不自动跟随链接/附件、不采用frontmatter授予工具权限。目标动作仍由原执行器校验，不让Skill加载伪装HTTP/local_command或进入目标请求审批。

### 计数与事实分层

推荐项目按Skill显示“成功加载次数”，并提供明细与模型调用关联；避免将含糊的“执行次数”作为唯一指标。

| 事实 | 来源与建议展示 | 是否增加成功加载次数 |
|---|---|---|
| 目录可见 | 有界发现结果；不表示正文已读 | 否 |
| 加载请求 | 平台受理具体逻辑加载身份，保留方向/目的 | 否 |
| 加载成功并提供给方向上下文 | 正文读取/完整性校验/来源固定/上下文结果在同一持久边界完成 | 是，每个逻辑加载身份一次 |
| 加载失败/超限/条目失效 | 真实失败结果，不能假装空正文成功 | 否 |
| 已纳入模型输入准备 | 与具体call_id及不可变加载结果关联 | 不额外增加；不等于已经发送 |
| 明确未发送 | 沿用调用账本not_sent | 不额外增加；明确没有此次发送 |
| 已尝试发送 | 账本attempted=true；transport_unknown与HTTP/有效响应分别显示 | 不额外增加；不能据此保证供应商已收到/理解 |
| 发送或收尾中断未知 | 账本interrupted/未知，恢复不补造成功 | 不额外增加；保留未知 |

同一加载结果被后续多轮携带不重复增加加载次数；可单独展示涉及的模型调用数。目录浏览、前端查看历史正文、重开页面、重启恢复和重复提交均不增加计数。明确新的加载请求若再次成功，可以产生新的加载记录；内部重试/恢复仍复用原逻辑身份。

最小记录需要项目/方向、触发Attempt、逻辑加载身份、Skill稳定ID及该次来源/hash、目的、时间和真实结果；实际进入模型输入的关联另绑定call_id。名称/目的是展示数据，目的属于Agent陈述，不能当作已执行方法的证据。持久约束保证重复回放不重复记账，汇总从权威明细派生，不维护第二套容易漂移的前端计数。具体类型、端点、索引与原子边界待下一实施契约冻结。

B账本的`attempted=true`仅表示进入请求尝试，不证明远端完整接收；`interrupted`的attempted可为空。Skill加载也不证明模型遵守或执行了全部指导。实际工具动作与漏洞验证仍需各自证据。

### 原文开关与兼容

- Skill原件/来源和最小使用元数据独立于逐轮完整模型原文归档；原文关闭时不得借统计保存整个拼接提示词或模型返回。
- 保留007和旧固定材料语义；后续以追加迁移和独立类型承接新使用事件，不覆盖旧任务。历史手工选材不能倒推成实际Skill使用记录，不为旧调用补造计数。
- 一次Attempt目前只有一条模型调用（迁移006唯一索引）。推荐新增只读研究活动、下一正常Attempt再调用，以保留此不变量；若未来必须同Attempt多轮，则另行设计调用身份/预算/恢复，不在本次偷改。

## 4. 已收敛的库定位与实施边界

原入口转达的问题选择结果为**“区分Skill与普通资料”**：两者共用同一资料库，显式设为可供Agent使用的Skill才参与自动发现和按需加载；普通业务资料仍显式提供给任务，不因入库而自动外发。名称/描述、目录和文本导入共用，无需两套存储或新主题。旧普通条目不自动转为Skill；文件名为SKILL.md、存在frontmatter或模型提出请求都不能替代显式分类。

统计采用上文“成功加载次数＋独立模型调用关联”的工程默认，现已由S1实现，无需再发计数问卷。一次加载被连续十轮携带不算作十次加载；当前字段、计数与发送事实见[正式契约](automatic-skills.md)。

产品选择已收敛，S1已冻结必要类型、端点、上下文容量和持久原子边界并完成本机验证。分页、锁、逻辑身份、CAS、哈希、索引和异常幂等属于工程落实，不要求用户选择数据库细节。本次实施不扩大真实供应商/目标、部署、外部投递或Git提交权限；未覆盖项与后续C2范围见STATUS§0.24。
