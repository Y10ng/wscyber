## 1. 已确认方向与工程建议

用户接受前一轮补齐方向：身份与业务规则、上下文选择、有限工作区连续性、持久化后的增量展示、敏感材料管理和有界恢复；强调先寻找优秀现成组件学习与复用，而非默认自研。用户进一步明确：

1. 目标流量记录必须提供；模型实际输入/返回记录改为可开关。
2. 增加类似文件夹的资料库，可存放 skill 并在运行时选用。
3. 增加可开关的禁止行为提示词限制；受控测试环境可关闭该附加约束。
4. 禁止行为与后续流量审批归入同一“测试安全”板块，后者仍延期。

以下未单独确认的默认值与实现细节均为建议，不写成已批准字段或现有能力。

**已实现增量（2026-11-12，A/B组）：** 全局多配置、自定义兼容接口/Header/参数、显式连通测试、默认/任务模型及实际研究已接通；当前实际适配OpenAI Chat Completions与Anthropic Messages，不宣称任意协议兼容。调用记录、按日/按任务tokens和手工价格估算已可用；关闭原文不关闭usage统计，未知不按零、币种不混加、估算不等于供应商账单。详见[模型配置与用量](model-configuration-and-usage.md)及STATUS。

## 2. 组件复用优先

先按功能寻找并比较成熟组件，再决定适配或自研；可以学习其机制，不默认复制源码、提示词或整体引入平台。评估上下文/skill 文件格式、受控文件管理、模型协议适配、HTTP 流量采集、证据展示与报告渲染等真实需求；运行时框架只有能解决实际问题才替换现有薄循环。

采用前记录官方来源、固定版本、代码与附带规则/模板/文档各自许可证、维护与兼容状况、运行依赖、数据外发及恢复语义，先做小型受控验证。区分“发现候选”“静态核验”“采用验证”“已集成”，不用项目名或宣传成绩代替测试。已有候选见[components](components.md)，本次未新增选型结论或依赖。

平台保留目标授权、业务归属、动作事实、发现编号与版本的权威；不让引入的框架产生第二套状态，不为复用接受自动重放未知副作用。

## 3. 目标流量必需，模型原文可选

### 目标流量

目标请求/响应是研究、验证、复测的必需证据路径，不提供随模型记录一起关闭的选项。具体工具/协议支持仍须按捕获矩阵验收；不能拿平台 HTTP 记录冒充全工具捕获。未发送、无响应、未覆盖、截断或捕获失败分别表达，不伪造完整报文。结构化请求或解码正文与逐字节线上原件区分。

对于承诺捕获的执行路径，持久层不可用或记录资源耗尽时停止新派发；对在途请求保留真实失败/未知与捕获缺口，不声称能追回未收到或未落盘的数据。

### 模型原文记录开关

**B组已实现：** 创建探索高级设置“保存模型输入与返回”，对应`record_model_content`，默认关闭；任务创建时固定，运行中不可切换。历史任务默认关闭，不补造记录。尚无独立的项目级默认设置，不能把早期建议当作已实现控件。

- 开启：在实际模型发送/返回边界保存业务输入/返回，提供受控读取；不能只存解析后的 Decision 或事后重构提示词。发送前输入保存失败不继续调用；返回保存失败保留错误/未知，不为补日志盲重试。
- 关闭：不持久化原始提示词、完整上下文或原始返回，也不通过日志、错误栈、追踪、调试转储绕道保存。运行仍需保存被采纳的决策/观察、动作/证据、任务状态，以及用于预算/故障诊断的最小调用元数据；这些不等于逐轮原文归档。自由文本派生内容仍按敏感材料管理。
- 关闭不影响目标流量记录和正常研究。原文读取接口明确“未启用记录”，不能把不存在的原文返回为空字符串并声称捕获成功，也不从可变模板重建冒充原文。
- B组按新任务创建时固定，不提供运行中切换。历史记录不自动删除，关闭期间不能事后补录；未来留存/删除或运行中调整需另冻契约，不能默认为现有能力。
- B组原文使用独立AAD的AES-256-GCM密文，只有鉴权后的显式content请求解密，缺/错钥不伪造成功；列表/汇总不加载密文。已知模型连接凭据从归档中移除并标redacted，研究Decision回显此类凭据时整次拒绝且保留usage，不改写动作后执行。不承诺任意业务材料通用脱敏；内容上限与具体语义见调用账本，长期留存/备份演练仍未完成。

模型原文关闭后，平台仍可复核已保存的动作与发现，但无法完整还原模型当轮收到/返回的全部内容，不能宣称具备完整调用审计能力。

## 4. 资料库与运行时 skill

**S1现行行为：** Agent根据研究状态/探索方向自主决定是否发现、加载或释放显式Skill，只作辅助而不驱动固定流程。创建时手工选择不是自动Skill的前置条件。普通资料仍须显式提供，只有分类为Skill的文件参与自动发现/加载；旧条目、SKILL.md和frontmatter不自动转换分类。正式库和项目“研究配置 → Skill使用”已接通；口径与容量以[automatic-skills.md](automatic-skills.md)为准。

### C1保留底座与S1增量

- 资料库已支持文件夹、单UTF-8 `.md/.txt`导入、创建编辑删除、元数据分页和显式原文。普通资料与Skill共用编辑器，Skill适用说明必填；当前仍是单管理员全局库，不宣称项目私有共享范围。
- C1旧显式选材路径保留：创建时最多16份/64KiB固定副本，后续库改删不改旧任务。它适用于显式提供材料，不再被描述为自动Skill的必经流程，也不倒算成Skill成功加载次数。默认关闭的附加安全清单独立保持。
- S1以`skill_discover/load/release`只读研究活动承接有界元数据发现、精确CAS加载及方向释放。一次Attempt仍最多一次模型调用，结果由下一正常Attempt消费；不在内层偷偷追加模型调用。
- 成功加载同事务固定来源/正文/hash及方向上下文，后续库改删不改历史。每方向最多4个活跃加载，正文65536字节、活跃集序列化98304字节，最终模型输入仍受原256KiB上限；超限明确失败，不截断冒充完整。
- 成功次数从不可变加载明细派生，目录/失败/释放/GET/同Attempt回放/重复携带不计；实际进入模型输入的call关联另记，Begin、not_sent、attempted、unknown不混同。加载不证明模型理解或执行。
- 原文归档关闭不删除Skill固定原件或最低使用事实，也不借统计保存整个提示词/返回。普通资料不自动外发，Skill不扩目标授权、不绕过程序保护；不执行脚本、安装依赖或自动跟随引用/附件。

### 早期建议与尚未实现的后续范围

本文早期的“创建时手选Skill后才可用”“按需加载相对引用附件”是方向收敛前建议，不是当前S1契约。前者已由显式分类加自主发现/按需加载取代；后者未实现。旧手选接口和固定材料仍兼容保留，历史记录不改写。

C2-B已支持带来源的人工非秘密文本补充：默认未分享，明确勾选后保存不可变原件，并在后续实际模型装配时携带；保存不自动启动、不改在途输入，实际调用关联与发送事实另记，见[研究控制与人工补充](research-controls-c2b.md)。尚不支持由用户指定某个未来生效轮次。更细生效控制、项目私有共享范围、敏感材料留存/删除策略、目录/压缩包与关联附件导入仍待单独范围及契约。若以后支持文件接收，需隔离接收、防路径穿越/符号链接逃逸/资源耗尽，并保持在途调用身份，不静默改写已发输入。知识图谱、向量检索、插件市场和执行型Skill不在当前已实现范围。

## 5. 测试安全：同一入口，区分软约束与程序控制

建议“测试安全”放在项目/任务设置中，显示本次有效配置，与资料选择、模型记录开关分别控制。

| 层级 | 用户体验与实际作用 | 首版边界 |
|---|---|---|
| 禁止行为提示词 | 开关 + 可编辑禁止行为清单；开启时注入平台管理的任务约束，关闭时不注入该附加清单 | 本次新增已确认；属于模型软约束，不保证发送前拦截 |
| 实际请求风险审批 | 对准备发送的具体请求做策略判断和必要的人工作出决定 | 完整新增流程仍延期；现有 G0 行为如实保留 |
| 目标授权与执行保护 | 明确范围、归属、资源限制、凭据隔离、未知不重放等程序检查 | 不由禁止行为提示词开关关闭；当前原生工具直连范围强制缺口如实说明 |

关闭禁止行为限制，表示在明确授权的测试范围内不再附加这组提示词限制，不等于全局关闭安全、扩大目标授权、放行旧 pending 或绕过现有 G0/HTTP 校验。若测试需要调整现有 G0 策略，应另行明确实际请求级配置与迁移，不把它隐藏在提示词开关内。

禁止行为清单由用户配置，不擅自固定一套禁止项；受控测试环境可不启用该附加清单。若启用，探索、独立验证和复测遵守各自任务的有效配置；导入的 skill 或目标响应不能覆盖它。界面在开关标签的按需Tooltip中提示“提示词约束，不保证拦截”，不添加常驻辅助说明。

运行时配置建议使用最小不可变快照，保存所选资料版本、身份引用、禁止行为配置与模型记录模式；不把这些扩写成覆盖账本或复杂 Profile 引擎。若后续允许运行中修改禁止行为，只作用于之后的派发；已经发送的请求不能撤回。

## 6. 接续与验收建议

先完成现成组件核验与最小契约，再按短轮次接通：目标流量/可选模型记录 → 运行中候选更新 → 独立验证 → 报告与复测。资料选用、上下文装配和禁止行为配置接入共同的任务配置，不另造调度器；具体切片与模板需共同确认，不一次开发全部模块。

必要验收：

- 模型原文开/关两条路径都能正常运行；关闭时原文不进入数据库、日志或追踪，目标流量仍保存；原文读取明确未记录。
- 开关改变不追溯删除或伪造历史，开启后的调用可定位实际记录，失败与未知不盲重试。
- 区分两条路径验证：普通资料仅显式选用并固定；显式Skill无需创建时手选即可自主发现/加载，普通条目不进入自动目录或正文加载。成功加载固定来源、受方向预算限制，更新/删除不改历史；目录/失败/重复携带不重计，实际call与发送事实另验。附件/引用不自动读取或执行。
- 禁止行为开启时正确装配，关闭时不装配附加清单；两种模式均保持目标授权与程序保护，明确不以提示词测试证明强制拦截。
- 任务尚在运行时发现可见且持续更新，断线/刷新后补读，候选不冒充确认，已保存材料不因报告失败丢失。

## 7. C3-A当前有界上下文与装配事实

正式研究路径先读作用域，再在同一PG快照装配获准固定材料、分享说明、活跃Skill、最近Skill活动和人工补充，以及有限历史：观察32/动作8/尝试8，额外最多16条显式反证和16条未决/效果未知动作。当前Attempt、最近观察/动作必需；超大必需项/必需项过多/总预算不足明确停止，不用摘要或追加模型调用掩盖失败。自由文本未分类反证可能在未读范围，不能依据模型未见判定不存在。

来源单项正文读取前检查64KiB，整条序列化历史96KiB，最终实际system+user256KiB。可选项超限保留未纳入引用与原因；不删原件、不条内截断，不将普通工作台/API和动作执行的全历史Snapshot偷偷改成子集。这些旧读取仍待后续容量治理，不宣称系统已全面有界。

每次实际模型call可显式查看不可变装配来源、字节及未读范围；来源元数据与call/Skill/Supplement关联同Begin事务保存。只存既有原件hash，不存正文/摘要/完整prompt hash，原文关闭也不重建冒充过去输入。保存不等于装配，装配不等于发送，attempted不证明供应商理解；旧call缺失记录明确未记录。普通未选资料和share=false不外发，装配后补充不追认进旧调用。

共享组件先行、正式React按需详情与本地20条分页已落地；关闭/换调用/401/迟到/错归属及503显式重读有专项证据。实际三路径两协议×原文开关、千条历史、实际输入比对、升级/PG/race及浏览器验收见[契约](research-context-c3a.md)和STATUS。真实供应商质量、长期容量、全部并发/整进程崩溃以及固定材料＋分享brief＋Skill满容量真实组合等尚未完整验证，不把已有单项通过外推为所有组合通过。
