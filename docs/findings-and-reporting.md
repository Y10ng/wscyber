# 发现编号、证据驱动报告、复测与外部对接

原目标讨论稿日期：2026-11-10；本轮补记实现边界。**下文长期目标不能全部当作现有API；D首片候选创建/更新、稳定编号、不可变历史和真实证据关联已有实现及首轮受控证据，已完成本轮受控本机验收及交回核对，见[实施契约](findings-incremental-d1.md)、[API现状](api.md)和STATUS§0.34；不代表真实研究质量或完整成果链路完成。D2随后已实现固定候选的显式独立有限验证、新证据和支持/反证/不足判读，见[独立验证契约](finding-verification-d2.md)及STATUS§0.36；这是工程证据，当前布局已被用户否定、未通过视觉验收。自动确认/完整确认流转、报告、修复后复测、外部对接仍未实现。** 下文示例`WSC-2026-000001`不是当前格式；D首片采用平台生成的`WSC-`数字编号及UUID身份，只有candidate状态，不实现全套管理流转。首版主场景已确定为 Web/API 漏洞挖掘。用户另已确认产品需包含流量面板、探索图谱、逐漏洞发现时间线、简洁且关联流量的漏洞详情、逐漏洞复测与报告，以及外部平台下发复测/接收结果；不要求第一步全部实现，具体分片与接口仍待确认。完整产品还包括其他研究场景和内部 SDL；首个研究切片不要求一次交付本文件全部能力。产品/运行时边界见 [vision](vision.md)、[architecture](architecture.md)，组件来源见 [components](components.md)。

**2026-11-11范围更新：** 外部平台实际对接首版延期，不阻塞本地漏洞验证/复测/报告。推荐发现、验证、复测使用独立任务上下文，验证实际权限与危害，低危与不成立分开；复测沿用原复现逻辑并核对有效身份/对照，不能以不可达或登录失败判修复。具体Agent方案仍待评审；用户当前要求优先确认整个挖掘引擎的质量/效率/深度/覆盖，不只增加验证Agent，见[研究引擎E0](research-engine-design.md)和[产品确认稿D1](product-confirmation.md)。

## 1. 各对象的权威

| 对象 | 职责 | 不代表 |
|---|---|---|
| Observation / Evidence | 观察与原始材料、来源、捕获边界 | 已确认漏洞 |
| Finding | 有稳定身份的候选问题及其版本 | 模型判定即可确认 |
| Verification | 支持/反证、复现前提、验证过程与结论 | 一次工具退出0就算验证 |
| Retest（暂名） | 对单个漏洞发起的新验证任务、执行记录与结论，绑定原发现版本及本次环境/身份/证据 | 覆盖原发现历史、盲目重放旧请求，或收到外部任务即获准执行 |
| Report / RetestReport（暂名） | 针对固定发现/证据版本或一次复测的可阅读交付物 | 自动发布或远端已接收 |
| Delivery | 向某个 SDL/其他获准目的地传递版本并取得回执 | 漏洞成立、修复完成或本地状态全部同步 |

研究模式可能产出非漏洞成果，例如 CTF 解题记录或演练覆盖证据。这些可进入相应报告，但不为了编号而强制创建 Finding。

## 2. 稳定编号与最小发现记录

建议由服务端为候选发现建立两种身份：

- **内部不可变 ID**：用于引用、关联与跨系统幂等，格式在实现时确定，不依赖标题、位置或严重度。
- **人类可读编号**：例如 `WSC-2026-000001`，只是示例，不是最终前缀承诺；由数据库原子分配，在部署命名空间内唯一、不回收。跨部署同步使用命名空间与内部 ID，不能只用顺序号。

编号在候选记录持久化时分配，**有编号不等于已确认**。重试不得生成第二份；合并重复发现保留别名/来源引用，不把旧编号给新问题。导出、重开、复测或修复不改变身份；内容变更增加 revision。

**2026-11-11用户补充确认：运行中即可持续查看发现及更新。** 候选形成后及时保存、分配编号并在漏洞列表/详情可见，无需等待任务结束或报告生成；明确区分待验证、已确认、证据不足等状态。证据、复现内容与验证结论随研究进展更新，保留版本和发现时间线，不把中间主张当作最终事实。暂停、局部失败或收尾失败不得隐藏或丢弃已持久保存的发现。

对应验收：任务仍在运行时，界面能自动更新已保存的新候选及同一编号的后续证据/验证结论；刷新后仍可读，更新不产生重复发现、不覆盖历史依据。具体刷新传输方式在实现切片中确定，不要求为此新增消息中台。

最小信息：

- 所属项目与场景、稳定身份/编号、revision、创建来源与责任归属（仅在实际身份能力存在时使用）。
- 标题、问题描述、受影响对象、前提、预期/实际行为、影响及限制。
- 动态位置：origin/接口/参数、身份引用、环境版本；静态位置：仓库标识、commit、相对路径/代码位置。不得只记录会漂移的行号。
- 证据引用、支持/反证、捕获截断和未验证部分；原件在受控存储中，不复制秘密进检索字段。
- 严重度及其依据；可选 CWE、CVSS 版本/向量/计算分数与业务影响。模型估分是建议，不将严重度当可信度。
- 修复建议、验证状态、修复状态、重复/关联信息和历史。

去重指纹是可版本化匹配线索，不是身份。自动匹配只能提出合并建议或遵循已验证的明确规则，不能静默丢弃不同身份、版本或影响面的证据。

## 3. 验证与修复分开

验证状态概念可包括：候选、待验证、已确认、证据不足、不成立；具体枚举与迁移在实施前冻结。至少保留验证方法、环境/身份前提、证据版本、支持与反证、判断者类型、理由和时间。

- 可由符合规则的自动验证流程形成结论，不要求每步人工批准；**不能仅凭生成发现的同一段模型文字自证成立**。
- 高影响、证据冲突或策略指定情况进入复核，不预设“每个漏洞必须固定三层专家”。
- 修复状态（未处理、已修复、复测通过、风险接受等）与验证状态分开，尤其避免 SDL 的“关闭”自动改写成“问题从未成立”。
- 复测使用新证据和环境版本，保留旧结论；复测没有复现不自动证明所有影响面已修复。

编号和结论依赖持久事务及真实证据，模型不能自主改编号、越权改变归属或伪造复核人。

## 4. 模型自动生成报告

### 输入与生成

报告任务固定项目范围、场景/profile 版本、模板版本、Finding revision 列表与证据清单。模型输入为获准处理的材料视图；敏感原件可保留受控引用，不能为了报告把所有认证信息发送给模型供应商。

模型负责组织描述、解释已证实影响、整理复现步骤和建议修复；程序负责编号、引用解析、模板/字段校验、版本绑定和格式生成。对于缺失字段明确“未提供/未验证”，不补造请求、响应、截图、利用结果、影响数量或修复效果。

### 报告结构（可随场景模板调整）

1. 项目/授权范围、时间、方法与限制。
2. 执行摘要、已验证结论与尚未验证部分。
3. 逐项发现：编号、状态、严重度依据、影响对象、前提、复现、证据引用、影响与修复建议。
4. 反证、例外、风险接受与复测说明（存在时）。
5. 证据索引与版本信息；敏感内容按发布视图脱敏。

代码审计强调 commit/路径/数据流证据，CTF 强调题目和解题证据，演练强调授权活动与验证结果；不把所有模式硬塞进漏洞列表。

### 草稿、发布与渲染

报告至少区分生成中/草稿/生成失败，以及正式发布的不可变版本；具体状态尚未冻结。修改材料后生成新版本，旧版本不被悄悄覆盖。草稿可自动生成，正式发布/向 SDL 投递需显式配置与授权，不默认跟随模型决定。

优先复用成熟模板和渲染组件。先交付结构化 JSON 与可审阅 Markdown，HTML/PDF 按需要选型，不为第一片自研排版引擎。Markdown/HTML 和附件均视为不可信输入：禁止脚本、外部资源自动加载和模板任意代码；必要渲染在无网络隔离环境中运行。

报告链接只指向稳定 evidence ID/revision，不持久保存临时下载凭据；按权限访问原件。脱敏是展示/交付派生视图，不改写原始证据。

## 5. 内部 SDL 的适配边界

不预设内部 SDL 的产品、URL、认证方式、字段、状态或附件接口；本轮不访问其服务。对接前需要真实接口契约和允许传输的数据范围。建议连接器作为可选适配层，不把外部平台当成本地研究状态数据库。

| 能力 | 要求 |
|---|---|
| 字段映射 | 本地编号、标题、影响对象、严重度、CWE/CVSS、描述、修复、证据与远端字段显式映射；不支持字段显式记录 |
| 身份映射 | 保存部署命名空间/内部 Finding ID 与远端漏洞 ID、SDL 项目/资产 ID 的对应关系 |
| 版本与幂等 | 投递固定 Finding/Report revision；本地事务保存投递意图与幂等标识，远端回执保存后才声明成功 |
| 未知结果 | 超时可能已创建；优先按远端幂等键或外部关联 ID 核对。无可靠核对能力时保留未知，不自动重复创建 |
| 附件 | 只上传获准材料，限制大小与类型；保留原件引用和上传回执，秘密/flag 不默默外发 |
| 状态回流 | 后续需要时再加；明确字段权威、版本与冲突处理，不把双向同步等同于最后写入覆盖 |
| 失败恢复 | 可解释的失败、重试策略和隔离队列；重试只重复交付同一版本，不触发重新测试目标 |

可先使用 PostgreSQL 内的事务投递记录（outbox 思想），不因此立即引入消息中台。即便本地提交幂等，跨系统也不能宣称恰好一次；远端能力决定核对方案。

外部连接器凭据只在控制面受控使用，不进模型输入、沙箱、浏览器持久存储或日志。自动投递只在用户明确启用且映射/脱敏规则生效后运行。

## 5A. 流量关联、发现时间线与简洁详情

以下功能已由用户明确提出；具体字段、交互与验收方案仍为设计建议，不是现有能力。

- 每个漏洞关联具体流量记录及版本；复现步骤可逐步关联请求/响应，支持直接查看和复制。一个漏洞可涉及多条流量，同一条流量也可能支持多个发现，不能只保存一段模型生成的“示例请求”。
- 流量使用稳定引用，记录所属项目、研究/验证活动、捕获来源及限制；未捕获、未发送或无响应应明确表达，不以拼接文本伪造线上原始报文。
- 每个漏洞有独立的发现时间线：展示与其相关的研究活动、验证动作、证据产生、候选记录和结论变化。以结构化来源关系关联事件，不从自然语言日志猜 ID，也不把模型事后生成的故事当作真实经过。
- 探索图谱展示研究活动、验证、流量/观察证据和发现之间的已保存关系；时间线按发生顺序呈现同一组事实。图谱是读取视图，不是新的事实数据库，也不意味着必须采用黑板或图数据库。
- **漏洞详情主正文只保留三个部分**：①漏洞描述，用几句话说明原理与危害；②复现步骤，简短直接，相关步骤就近查看/复制具体请求和响应；③修复建议。编号、标题与状态置于简洁页头；时间线、图谱关联、支持/反证、版本和复测记录放在按需展开的区域或独立页签，不把全部内部字段堆进正文。
- 详情简洁不等于删去复现所必需的身份、环境、步骤依赖和结论限制；缺少依据不得生成可冒充真实复现的报文。复制仅复制所选材料，不自动向目标发送请求；原件与脱敏视图必须区分。

## 5B. 逐漏洞复测与双向外部任务对接

### 已确认的产品功能

1. 每个漏洞可发起复测，每次复测保留独立报告记录，可以回看多次复测结果；不能用最后一次结果覆盖最初发现及此前复测。
2. 平台可按外部系统规定的固定格式，将复测结果发送到指定接口。
3. 外部系统也可把漏洞信息提交到平台，创建复测任务；不要求漏洞最初由本平台发现。

### 建议的数据与执行边界（尚未冻结）

- 区分复测任务、执行尝试、验证结论、报告版本与外部投递；任务收到/运行结束/报告生成/远端接收分别记录。编号关联原漏洞，每次复测有独立任务身份，执行重试不能重建同一次任务。
- 固定原漏洞版本及复现材料，绑定本次目标、环境、测试身份、有效授权和验证范围；保留新流量与支持/反证。所谓复测是新的受控验证，不是绕过请求策略的一键重放。
- 执行状态与漏洞结论分开。结论至少能表达“仍可复现”“本次验证范围内修复已验证”“无法判定”；枚举和通过判据另行冻结。登录失效、目标不可达、材料不完整或仅未复现不能自动判为已修复。
- 复测报告建议简洁呈现本次结论、测试范围/环境与时间、验证步骤、新请求/响应证据、与原问题的对照及未验证部分；报告生成失败不覆盖已保存的执行事实。
- 外部提交先鉴权、校验任务关联与去重标识，并与本地项目/授权范围匹配；外部漏洞文本、URL、附件及其所谓授权声明均是不可信输入，不能扩大权限或直接执行携带的命令。材料/授权不足时保存为待补充或拒绝，不默认访问外部目标。
- 入站任务在本地可靠持久化后返回回执；同一个外部任务重复提交不能重复启动目标测试，修改任务内容须有明确版本/冲突语义。新一轮主动复测与网络重试必须区分。
- 出站结果使用固定版本的字段映射，保存外部任务/漏洞 ID、本地关联、报告版本、投递状态和回执。接口超时先核对；重试发送结果不能再次触发复测。复测完成与结果已送达分别展示。
- 不接受入站载荷中的任意回调地址作为可发送目的地；外部连接器、目的地址、认证和可传输材料须预先明确配置与授权。外发证据按约定脱敏，不附带模型或工具运行凭据。

外部平台是否与 SDL 相同、采用推送回调还是结果查询、请求/响应格式、认证、字段/结论映射、去重与回执机制均未提供；只保留适配职责，不猜接口或实施对接。登录态/多身份方案也仍待用户确认。

## 6. 复用与标准取舍

- DefectDojo 可作为可选漏洞管理适配目标/导入去重参考，不要求取代内部 SDL，也不默认随本平台部署。
- SysReptor 等报告系统可评估模板/渲染或外部报告服务边界；许可证、部署和数据暴露要求核验后才能引入，不能把公开源码视为任意可嵌入。
- SARIF 2.1.0 适合静态分析结果交换；不能替代完整渗透报告、动态证据和 SDL 生命周期。CWE/CVSS 使用明确版本和原始依据，不自动产生 CVE 编号。
- 具体公开来源、可复用能力与许可证状态见 [components](components.md)；本文件不把候选写成锁定依赖。

## 7. 分片与验收

建议先稳定流量证据/结构化关联及 Finding 编号，再交付简洁详情、发现时间线与报告；探索图谱读取同一事实关系，可独立分片。逐漏洞复测及其报告、外部复测入站/结果出站分别交付，外部对接依据真实协议；不要求它们与 SDL 同时完成，也不因后续报告一次做完整漏洞运营平台。具体顺序仍需用户确认。

验收至少覆盖：并发/重试编号唯一；候选与确认区分；重复合并保留身份；漏洞步骤能定位并复制对应真实流量；图谱/时间线不编造来源关系；报告引用可解析且版本固定；缺证据不编造；脱敏不改原件；不可信渲染无网络；远端创建成功但回执丢失不重复创建；修复与验证状态不串改；复测保留原结论和新证据；登录失败或不可达不判修复通过；重复外部任务只创建一次复测；越界任务不派发；结果投递重试不再次测试目标；任何失败不盲目重放目标请求。

本轮只定义方向和约束，未冻结字段、接口或迁移；未安装报告工具、未生成真实项目报告、未接入 SDL。
