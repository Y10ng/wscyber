# 界面实现依据（设计稿落地，2026-11-20）

**设计源：[设计稿.html](设计稿.html)**（用户 11-20 确认满意）。浏览器直接打开即可交互：顶栏切页（总览 / 漏洞卡 / 漏洞列表 / 设计规范 & Tokens）、状态与视角下拉、1440/1280/≤768、深浅色。实现以它为准；本文只写**与现有实现的映射、数据来源与缺口、分片**。`ui-shell.md` 中与设计稿冲突的尺寸/配色以设计稿为准。

## 1. 设计 Token → 实现

- 设计稿 `:root` / `.dark` 中的 `--bg-*`、`--border-*`、`--text-*`、`--brand-*`、`--sev-*`、`--st-*`、`--disp-*`、`--code-hl-*` 全部原样加入 `native/ui/source-overlay/src/index.css`（浅/深两套），并把原生 shadcn 变量（`--background`、`--card`、`--muted`、`--border`、`--primary`、`--foreground`、`--muted-foreground` 等）映射到对应设计值，使未改写的原生组件也统一到新配色。
- 字体：Inter / Noto Sans SC / JetBrains Mono（已有变量，核对一致）；数字 tabular。
- 七个维度的徽标做成共享组件（一处定义，全站复用）：状态（圆角胶囊 + 圆点）、等级（实色微底 + 描边方角；AI 建议为虚线框 + 星标）、处置（4px 锐角 + 语义图标；误报弱化删除线）、期限（正常 / 即将到期 ≤2 天 / 逾期 N 天）、工单、验证判读（+“模型判读”弱标签）、复测结论。

## 3. 设计稿未覆盖的页面（用户 11-20：同样要达到设计稿效果）

设计稿只画了总览、漏洞卡、漏洞列表；其余页面一律按设计稿的设计语言改造，不保留旧风格。规则从设计稿归纳：
- **页面骨架**：页头（标题 20px 600 + 帮助图标 …… 次要 outline · 主操作 primary）→ 筛选胶囊行（选中品牌实底白字，带计数；搜索框在胶囊行右侧）→ 内容卡片（bg-surface、1px border-default、rounded-lg、无重阴影）。
- **卡片标题行**：14px 600 + 右侧“查看全部 →”/区块操作；卡内 16–20px 内边距。
- **表格**：表头 bg-subtle 12px 600 text-secondary；行 ≥56px（两行内容）或 48px（单行）；状态/等级/处置一律用共享徽标组件；数字右对齐 tabular；端点/ID 用 JetBrains Mono 12px；操作列图标按钮。
- **详情多栏**：主栏 + 右侧 360–400px 信息栏（参照漏洞卡）；列表|详情两栏之间 1px border-default。
- **HTTP 原文**：凡展示请求/响应（流量详情、验证证据、黑板证据、复测）统一用漏洞卡的“请求/响应并排代码块”组件：行号、方法徽标、关键行高亮（code-hl）、折叠非关键头、复制/截图/遮盖敏感值。
- **时间线**：生命周期/事件/Oracle 事件统一用漏洞卡右栏的竖向时间线样式（圆点状态色 + 标题 + 次行说明 + 右侧时间）。
- **表单**：标签 12px text-secondary 在上；输入 h-9/h-10；分区之间用细分隔线与 14px 600 小标题（参照漏洞卡“处置与定级”卡）。
- **时间格式**：中文 `YYYY-MM-DD HH:mm` / 列表内 `MM-DD HH:mm`，不用 AM/PM。

逐页清单（UI-C 分批，每批截图与设计稿并排对照）：任务列表与计划队列；任务工作区（顶栏、执行时间线、流量列表与详情、候选列表与详情、黑板、报告、用量）；验证/复测/报告会话页；资产列表与详情（基本信息、测试账号、周期计划、运行记录、漏洞库）；报告列表；集成（企业微信配置与推送记录）；模型、节点（原生卡片包外观统一）；登录页（WScyber 品牌）；各 Dialog/Sheet/Popover。

## 4. 分片（前端 ds-flash，后端 o-latest）

1. **UI-A 设计基础**（前端）：Token 与原生变量映射、七类徽标组件、侧栏按稿、漏洞列表按稿；全站深浅色走查。
2. **OV2 总览后端**：overview 增加 `todo{unrated, pending_push, pending_approval, overdue}`、`sla{rate, avg_fix_days_by_severity, overdue_top}`、`coverage{tested_30d, total, stale_top}`、运行中任务的黑板覆盖率、最近确认带 severity。→ **UI-B 总览前端**按稿。
3. **K1 漏洞卡后端**：验证结果增加最小复现结构（impact、preconditions、key_steps[{title, evidence_id, highlight}]、contrast{normal, abnormal}、remediation[]、retest_method、suggested_severity+理由），漏洞详情聚合接口（模板化标题、最小复现取代表成员最新 supported 验证、生命周期、同资产其他漏洞、curl 生成）。→ **K1 前端**按稿。
4. **UI-C 全站按设计语言改造**（前端，分 3 批：① 任务列表 + 任务工作区各视图；② 资产、报告、集成、模型/节点、登录；③ 验证/复测/报告会话页与全部弹层）。与后端片穿插进行。
5. **K2**：一键重放（授权范围内确定性重放 + 存证 + 比对复测方法期望）、报告/推送从漏洞卡生成。

顺序：UI-A 与 OV2 后端并行 → UI-B 与 K1 后端并行 → K1 前端 → UI-C ①②③（期间后端做 K2、M5）。产品名 **WScyber**（用户 11-20 指定）。
