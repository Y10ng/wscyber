# UI-1：历史界面基线与可演进组件资产

2026-11-11 用户明确认可当前 compact 版，要求固定规范、新开主会话逐轮开发，并允许后续功能按需求调整布局。本文是视觉与交互基线，不是业务能力或未定后端契约的批准声明。当前参考实现为 `web/src/design-preview/`，独立演示入口不等于正式产品入口。

## 0. 最新执行顺序（2026-11-13覆盖旧约束）

**当前布局已被用户否定；先学习优秀项目实际设计，再决定组件与布局如何改进。** 见[界面整改方向](ui-redesign-direction.md)。`web/src/ui/`和`component-preview/`是实现资产/用例，不是禁止改变信息架构、布局、排版或视觉层级的理由。Ant只提供底层控件，不是整页设计方案。保留合适的组合，改造不合适的组合，再统一沉淀与回归，不让各页分裂成多套主题/业务状态机。

用户已授权在过程中自主学习改进，不再受此前UI-1固定布局/像素约束，也不是“只整理文档”。当前先重构任务工作台、候选及验证的真实展示；下列旧参数/工作面规定是历史实现起点，冲突时以最新反馈和整改方向为准。授权、证据真实性、秘密隔离、可靠提交与可访问性保护仍必须落实；不能把改视觉等同扩大产品或执行授权。

## 1. 固定什么，允许调整什么

**必须保留：** 业务真实性、授权/敏感材料边界、可靠提交与恢复、证据保真、可访问性及统一实现；React/TypeScript与既有Ant作为当前工程基础，不为视觉问题无依据更换整个技术栈。

**已获准有依据改进：** 外壳/导航、内容分区、列表与详情关系、正文宽度、信息层级、排版/密度/表面、控件组合、页签和弹层方式。以实际参考与清楚可用的体验为准；可以整体重构被否定的工作台，不再受原UI-1像素/组合约束，不为普通UI改进反复确认。涉及新的产品能力、后端语义、数据/部署授权或新增依赖时仍按相应规则处理。

不为填满页面编造统计、假内容或无意义卡片；也不以统一窄 max-width 造成大面积空白。真实内容较少时允许自然留白。

## 2. 主题、排版与几何

唯一 token 来源集中在 `web/src/ui/surface.ts`，由 `UIProvider.tsx` 统一应用至文档与Ant portal；设计入口的 `surface.ts` 只保留业务辅助函数并重导出共享token。不得再复制一份主题。正式React已接入单一共享Provider、浅暗主题、AppShell与可靠创建TaskModal；业务草稿、幂等键和提交核对仍归正式App，不迁入演示状态机。

| 语义 | 浅色 | 暗色 |
|---|---|---|
| 页面底 | `#f5f5f3` | `#0b0b0a` |
| 主工作面 | `#fcfcfb` | `#151515` |
| 内嵌面 | `#f0f0ee` | `#1a1a19` |
| 抬升面 | `#f8f8f6` | `#20201e` |
| 正文 | `#303530` | `#e3e5dd` |
| 次要文字 | `#636961` | `#aaafa5` |
| 主交互 | `#2f6fed` | `#6f9bff` |
| 选中底 | `#eaf0fc` | `#222b3c` |

- 不用纯黑 `#000` 或常驻描边拼出卡片；主要用微明度和间距分层。必要键盘焦点必须可见。
- **2026-11-11最新UI反馈覆盖旧16px底线**：正文、表格、表单、状态、时间、placeholder、Tooltip与错误统一14px；标题常用16/20/22px。降低冗余间距，不用更小文字塞说明。最新调整尚待用户实际视觉评审，不能继承旧compact模板的认可。
- 浅色 regular/medium/strong/heading 为400/500/600/650，暗色为360/460/560/610。计算样式差40不代表所有系统字体都能连续栅格化减40；需看真实截图。
- 数字 `tabular-nums`，正文 `text-wrap: pretty`，行内图标 `vertical-align: -0.125em`。长状态/资料名换行，不挤出隐藏的横向内容。
- 常用间距4/6/8/12/16px；正式Card内边距16px、工作面圆角12px、控件10px、任务Modal20px。状态/时间/操作尽量同排，正文长内容自然换行，不强制每个功能点一行。
- 正式桌面侧栏208px、折叠64px，内容跟随最大化浏览器可用宽度；演示业务模板列宽仍可按功能调整。桌面控件36px/紧凑32px，触屏主要按钮至少40px，保持键盘操作与可见焦点。预览使用响应式viewport，不能用固定1440px视口冒充最大化效果。
- focus 不新增 outline；浅色双环 `#dce7ff` / `#7098e8`，暗色 `#293854` / `#6f9bff`，扩展2px/4px。键盘与鼠标聚焦都应清楚可见，不以去边框为由删除焦点提示。

## 3. 工作面与弹窗

- 全局左导航按真实能力开放；模板展示研究项目/流量中心/资料库。正式产品不能仅因模板有入口就展示假功能。
- 顶栏只保留当前项目范围、必要状态、配置、新建项目。研究内组织研究、发现、模型记录；未来报告等跟随真实能力加入，不固定所有未来页面。
- 研究优先当前问题、依据、下一步和必要控制；宽屏正文/活动并列，信息不足时不硬分栏。
- 发现正文仍为漏洞描述、复现步骤、修复建议；证据/验证/历史按需查看。网格避免长列撑出另一列的行间空洞。
- 项目内报文复用检查器，保持当前页签、DOM、阅读滚动及关闭后焦点；只在用户明确操作时进入全局流量。切项目核对归属并清理旧敏感视图。
- 全局流量采用类Burp列表与下方报文工作面；请求/响应桌面双栏，可拖动分隔、键盘调整、筛选/排序/搜索/复制。窄检查器可上下排列。不因此承诺代理、重放器、扫描器或全协议捕获。
- 新建项目、任务配置、补资料使用居中 Modal，不用侧边 Drawer。当前参考宽度880/920/800px，不是所有新表单的硬尺寸。
- Modal 限制在视口内；最大高度 `calc(100dvh - 48px)`；header/footer不收缩，body局部滚动。表单错误定位到相关处；关闭保留未提交草稿（明确重置除外）。共享TaskModal及遮罩固定无进出场动画，保证动态减少动效下关闭生命周期不依赖零时长动画事件；不影响草稿、串行切换或焦点语义。
- 弹窗串行切换，不叠加焦点陷阱；Tab/Shift+Tab首尾循环、Escape关闭、焦点按触发来源归还。Ant6使用 `focusable.focusTriggerAfterClose`；当前三种任务Modal有局部Tab补偿，提取复用时保留测试，不修改依赖。

## 4. 动效与反馈

- 新流式文字：单字90ms、相邻30ms错峰、blur6px至清晰；`cubic-bezier(.215,.61,.355,1)`。不能把一次性历史正文假装成实时模型流。
- 折叠用Grid `0fr → 1fr`，不JS测scrollHeight；收起内容 `inert` + `aria-hidden`，不留不可见可聚焦控件。
- 拖拽：stiffness1200/damping80/mass1过阻尼；对勾：380/18/mass1欠阻尼。拖动跟手，释放稳定，不用无关Bezier冒充已验证弹簧。
- 复制实际成功才显示对勾；2500ms后恢复，淡出180ms；重复复制重置计时，卸载/换记录后旧异步结果失效；失败如实反馈。
- `prefers-reduced-motion` 取消动画与错峰，保留全部信息和完成回调。短全局通知直接显隐（当前 `AntApp.message.transitionName: ''`），避免动态媒体切换导致离场DOM残留；保留必要内容和关闭计时。
- 去掉重复全局通知；局部状态已足够时不再弹同义成功提示。2026-11-11后续反馈明确禁止常驻小字辅助说明/解释段，不能放大字号或搬位置规避；只保留真实任务内容、操作、授权输入与真实状态，错误和必填校验在实际触发处显示。HTTP/bridge等能力边界留在开发/API文档，不改变授权、执行或unknown行为。

用户补充要求：**写好实际组件库作为固定参考，覆盖项目规划中可能用到的组件**，不止规范文档。实现可点击组件展示页、共享主题/样式/交互原语与业务组合组件；覆盖基础控件到研究工作面，按短轮次补齐覆盖矩阵。官方Button/Input等基础组件以统一主题和标准用例复用，不为形式统一重复封装全部API；这不缩减展示与验收覆盖。组件库不是额外建设权限/发布/版本管理平台，也不宣称能够预见所有未来需求。

## 6. 业务与数据边界

- 资料是方法参考，不授予目标权限；固定版本，运行中补充从后续轮次生效，不回写历史模型输入。
- 模型原文开关的演示行为是启动时固定；关闭时原文实际为null，不是仅UI隐藏。正式持久化、权限/留存/API契约需在对应轮次冻结，不能由UI默认值自动批准后端存储。
- 禁止行为提示词只是软约束；关闭不扩大授权、不撤销程序保护。
- 候选不等于验证成立，编号不证明有效；运行中可持续更新，保留历史，不等收尾才展示。
- unknown不自动重放，提交待核对不等于目标效果未知；敏感头默认遮蔽，切记录/项目与关闭重开复位。
- 已保存字节的文本/hex/Base64只是视图。复制按钮须明确指向当前预览或当前可见头；下载保持完整已保存原字节。预览上限与捕获截断分开；未提供字段不能证明0字节。关闭、换对象/材料/模式或401使旧复制反馈失效，但不能承诺撤销浏览器已接受的剪贴板写入。
- 不可信HTML/模型/目标内容只作数据，不执行脚本、自动加载外部资源；秘密/草稿默认仅内存。

## 7. 每轮验收

1. 新功能用真实已存在API或明确隔离fixture验证；服务端状态为权威，不用演示成功顶替业务完成。
2. 类型、构建与针对性逻辑检查；涉及共享原语时同时回归设计示例和正式入口。
3. 实际最大化浏览器（记录真实窗口/viewport）及1440×900与1920×1080浅暗布局；查看截图，检查内容宽度、层级、溢出、弹层与长文本。390px移动端保留可操作底线，具体覆盖如实记录。参考站点只读观察遵循 [界面参考](ui-reference.md)。
4. Modal正反向Tab、Escape、来源焦点、草稿、错误与长表单；项目内证据保持上下文；动态减少动效与复制计时。
5. 可见正文/表格/表单/提示14px、标题有层级，未使用小于14px文字；无控制台正常路径错误；不可信内容、敏感头、归属、过期响应、写入失联与存储边界随本轮行为验收。
6. 技术通过与用户设计批准分开。UI-1已由用户认可；新增功能合理调整布局属于正常实施，不要求每次推翻基线。

UI-1实现验证记录见 `var/session-round.compact.bEgdFUTq/outcome-main.md`：19组契约、10组交互、4组布局专项通过；构建仍有>500kB chunk警告。临时证据不作为正式业务契约。
