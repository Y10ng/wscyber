## 1. 已确认功能

- 全局管理产品 Agent 使用的模型配置，不限于 GPT/OpenAI、Anthropic；支持其他供应商及自定义兼容服务。全局可保存多个配置，不将某一家供应商写死为唯一后端。
- 可配置接口地址、模型、认证、自定义 Header 和请求参数；提供用户显式触发的连通性测试及可解释结果。
- 记录实际模型调用的 tokens 用量，提供计费能力；仪表盘可查看每天的 tokens 用量，以及每个任务的 tokens 用量。
- 此处是 **wscyber 产品配置**，不修改开发 CLI/harness 的模型、Header 或全局设置。

## 2. 配置与兼容边界（工程建议，待冻结）

- 区分供应商协议、连接配置和模型条目。相同 HTTP 地址形状不意味着工具调用、流式、usage、错误和缓存计费完全兼容；只声明逐项实际验收的协议/能力。
- 允许显式 endpoint、认证方式、自定义 Header 和扩展请求参数，先冻结保留字段/覆盖优先级及非法值校验。不能把“自由配置”实现为执行任意脚本、加载代码或绕过模型数据外发授权。
- 全局配置供任务选择默认或覆盖；任务和实际调用固定配置版本/模型标识。具体默认模型与选择粒度另定，修改全局配置不悄悄改写在途调用或历史账目。
- 密钥与可能携带秘密的 Header 受控保存，列表默认遮蔽；原值读取、轮换、删除、加密密钥和备份策略在实施前确定。凭据不进入模型业务原文、浏览器持久存储、日志或导出；不用目标 origin 白名单隐式授权模型供应商的数据接收。
- 连通测试由用户明确点击触发，不自动向每个配置批量发送。发送前说明会外发最小测试内容且可能产生 tokens/费用；不携带项目证据或真实目标凭据。超时/失败不自动无限重试，不把“配置已保存”说成“模型可用”。
- “网络可达”“认证通过”“产生有效模型响应”“支持某项 Agent 能力”分别记录；连通成功不是研究效果验证。

## 3. 用量账本与费用口径（工程建议，待冻结）

- 在实际发送/返回边界记录独立调用身份，并关联任务、方向、尝试和用途；每次实际重试单独记录。供应商回执或本地保存重试不能重复计数，也不能漏掉失败/取消时已返回的真实 usage。
- 至少区分输入/输出 tokens；缓存读写、推理及其他分类按供应商真实定义保留，避免将子集与总量相加导致重复计费。不支持或未返回的字段记未知，不假造零值或按文本长度冒充供应商计量。
- 用量元数据不依赖“保存模型输入与返回”开关。原文关闭时仍统计可取得的实际 usage，但不得为计费旁路保存提示词/返回正文。原文开启也不意味着每个失败调用都有完整 usage。
- 费用由明确价格表计算时标为**估算费用**：价格绑定供应商/模型、单位、币种、生效版本及计费分类。人工自定义价格、历史价格变更、缓存阶梯与币种处理在实施前冻结；修改价格不默默改历史账目。
- 实际账单仅在存在可信供应商账单来源时另行显示，不能把估算当供应商扣费。未知 usage/未配价格分别显示不可计算，不能在汇总中隐藏缺口或按零计费。
- 按日统计的时区/归属时间，以及跨日调用、失败、重试、系统连通测试、无任务调用的汇总口径需明确。连通测试不能虚挂到某个研究任务；每日总量与任务明细可核对。

## 4. 仪表盘与任务视图（目标，不是现有页面）

- 仪表盘：按日的 tokens 用量及选定期间汇总，可按模型/供应商查看；费用仅在有可靠计价依据时展示，并标明估算/币种/未知部分。
- 任务：查看该任务的输入、输出、总 tokens、可计算费用及调用明细；探索、后续验证/复测/报告关联规则在各实体落地时明确，不靠自然语言或时间接近猜归属。
- 用同一持久调用账本聚合，两处不各自维护计数器；刷新/重启不丢账、不重复累计。先服务单管理员本地产品，不因此新增多租户财务平台或支付结算。
- 本次只记录需求，不添加可点击占位导航、假用量/费用或演示仪表盘冒充真实数据。

## 6. MC-1现有实现记录（A/B1/B2已验证，设置页暂停）

### A：全局配置管理

- 每项配置独立32位小写hex ID，`revision`从1递增；创建请求`expected_revision=0`，编辑必须匹配当前版本。最多100项，列表完整返回。重复提交同ID/旧版本返回409，不再建一项；写入失联先GET核对，不自动重发或换ID。
- `name/protocol/base_url/model/auth/timeout_seconds/max_output_tokens/enabled`是普通可读字段。协议为`openai_chat/anthropic_messages`；A保存选择，B1提供两协议组件、B2已接入正式连通测试API；研究任务尚未接入。认证为`none/bearer/api_key`，OpenAI Chat只允许前两者。超时1–600秒、输出上限1–32768。保存不证明供应商支持具体参数。
- `api_key/headers/parameters`各自提交`{mode:"keep"|"replace"|"clear",value?:...}`；replace必须显式给value，keep/clear不得带value。读取只有`api_key_set/header_names/parameter_keys`，不提供秘密值读回。Header和参数值全部按秘密处理，不只掩盖名称像token的字段。
- 完整配置文档用标准库AES-256-GCM密封，随机nonce、AAD绑定配置ID/版本；PostgreSQL只保存密文及ID/版本/启用状态/时间。`WSCYBER_MODEL_ENCRYPTION_KEY`必须为标准base64的32随机字节，缺失禁用管理API，错误/丢失不自动生成替代密钥。配置与数据库分别备份；没有在线主密钥轮换、删除或回退接口。历史版本不可变，clear只影响新版本，历史凭据仍以密文保留。
- 改变协议、端点或认证方式时，不能keep已有key/Header/参数；须显式替换或清除，避免把旧秘密静默带到新接收方。配置级禁用保留历史；未来运行解析遵守禁用状态，不假称撤销在途请求。
- endpoint无userinfo/query/fragment或路径穿越歧义；远程HTTPS，明文HTTP仅字面loopback。自定义Header拒绝控制符、大小写重复、认证/Host/Content/连接/代理/转发/SDK控制字段。扩展参数仅接受顶层ASCII标识键、有界JSON，拒绝重复键、深度超过16与模型/消息/工具/stream/token上限等保留字段；不将键当SDK路径表达式。
- 默认选择有独立CAS版本，只能选择当前存在且启用项，空ID清空。**A阶段仅保存选择，尚不改变旧环境模型或启动任务。** 所有管理API沿用Bearer/同源/no-store，不记录请求正文、秘密或远端原文；无后台自动连通测试。

### B1：内部协议组件（已完成本地验证）

- `modelprovider.Complete`使用官方OpenAI/Anthropic SDK；分别在base后追加`chat/completions`和`v1/messages`，不裸请求Base URL。OpenAI的base应包含该供应商要求的API版本前缀（例如`<网关前缀>/v1`），不是完整生成接口；实际请求路径由配置与协议拼接，固定后不猜路径/切协议或自动回退。用户提供的网关前缀已在其授权下由主补齐标准`/v1/chat/completions`并得到有效响应，不能据此把所有自定义服务强制改成相同路径。显式端点、认证、HTTP client；不继承环境凭据/Header/代理，不重定向/自动重试，不执行工具返回。
- 每次单独HTTP/1.1连接，单次解析后检查全部IP并只拨选定IP；拒绝unspecified/link-local/multicast，保留正常TLS主机名/SNI/证书校验。远程HTTPS、HTTP仅字面loopback。
- System＋User合计256KiB，最终序列化请求体2MiB，均发送前超限拒绝。响应头32KiB；完整响应体最多1MiB，读取中断或超限为unknown；提取文本最多32KiB，完整回执后文本超限/格式不合为invalid_response。严格拒绝重复JSON键、损坏Unicode、错误字段类型及非正常结束，不能用SDK宽松解码冒充成功。
- 返回`not_sent/transport_unknown/http_error/invalid_response/valid_response`、HTTP状态及内部Text。Text不经JSON暴露；没有usage字段，不把未知tokens记零。Attempted只表示进入传输，不能证明供应商收到请求或未计费。组件本身不持有配置ID/版本、enabled或跨调用幂等身份。

### B2：持久连通测试（已完成本地验证）

- 正式POST/GET接口见[API](api.md)。严格接收精确`config_revision`与`confirm_billable:true`；先持久受理再发送，新身份202、同身份回放200、冲突409。历史回执优先于当前配置版本/禁用/密钥与容量；受理事务再次核对身份并与保存/禁用串行化。回执无供应商内容或秘密，缺省attempted代表未知，不是false。
- 容量8包含运行中的1项，单worker。只发送固定`Reply with OK.`、无system/项目材料、至多32输出，持久用途为connectivity_test/request_version=1。HTTP断开不取消已受理测试；按精确旧版本调用，发起前检查最新enabled，不能用新密钥/端点替换已确认版本。
- 正常关闭使用独立有界context保存；启动将旧pending/running保守终结unknown，不重发。领取/写回/已检测失锁故障停止执行，终态不可被迟到结果覆盖。不能承诺最后enabled/锁检查与真实发送无时间窗、撤销在途或外部恰好一次。
- 真实程序本地fixture验证两协议、重复/并发、超过30秒供应商等待的快速受理、客户端断开、正常停机/SIGKILL恢复、缺密钥回放及持久失败。真实供应商仅有主另行授权的B1最小请求成功，不冒充B2完整真实供应商链路或研究质量验证；未造usage/费用。
