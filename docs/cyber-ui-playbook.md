## 3. 按阅读任务组织，而不是平均分配卡片（R，依据V）

### 3.1 三层职责

1. **全局导航**：切换任务、成果、资料与配置等已经实现的对象；不在每个对象页面重复铺同一套入口。
2. **任务上下文栏**：返回、当前任务、真实状态和必要元信息、视图切换及任务级控制。状态、时间、用量尽量同行，不各占大卡片。长标题截断但可查看完整标题。
3. **当前工作面**：执行过程、工具记录、流量、发现或报告。局部导航选择“看哪类记录”，中央区域负责阅读与操作；辅助详情按需出现，不能空占一大栏。

任务创建仍遵循本项目“两主要输入＋明确授权”，不能照搬参考图中的内部角色/Map配置作为必填步骤。产品不绑定黑板架构，也不把每条推理/工具动作变成人工审批。

### 3.2 各类页面采用不同骨架

| 阅读任务 | 采用的骨架 | 不应采用 |
|---|---|---|
| 找到任务 | 标题/搜索/主操作 → 状态筛选 → 行列表 → 分页 | 大欢迎区、假KPI、每条任务一块巨型卡片 |
| 理解探索进展 | 方向/对象选择 → 时间线或原生执行流 → 就地展开证据 | 把所有原始JSON平铺成对话、只给装饰图谱 |
| 查工具调用 | 过滤栏 → 调用表 → 所选调用参数/结果 | 为每个调用重复整组任务说明；把未判定当放行 |
| 查HTTP证据 | 记录选择 → 同一记录的请求/响应 → 来源与捕获状态 | 请求/响应分属不同选择、先自动拉全量原件、用模型摘要冒充原报文 |
| 阅读报告 | 目录＋有限行宽正文＋就近证据＋独立导出操作 | 将正文横跨整个宽屏；把运行日志全塞入报告主文 |
| 编辑模型 | 有界居中表单、明确标签/单位、固定主要操作 | 配置版本管理、秘密keep/replace/clear流程、每字段多行解释 |

参考V2是“上列表、下双栏”；固定原生TrafficPanel在大屏是“左列表、右详情”（S）。这是真实结构差异，不能把组件名字相同称为视觉一致：优先保留原生请求/响应渲染器，按工作区用途组合外层布局，必要偏离写进任务包。

## 4. 文字、密度与对齐（R）

- 标题负责定位对象；正文负责理解内容；元信息负责时间/来源/数量。最多少量稳定层级，不靠遍地小灰字表达层次。
- 常用名称和状态保持可读；时间、ID、耗时、计数采用稳定列与一致单位。正文左对齐，数值列按适合比较的方式对齐，操作列位置稳定。
- 工具名与参数/结果预览形成明确主次；长预览单行省略或有界多行，完整内容通过真实展开读取。不要靠极小字号塞全量日志。
- 说明只在有操作价值时出现：必要字段标签、单位、风险、缺失前提、当前错误必须保留；重复标题的介绍、常识解释、开发实现说明不常驻。
- 列表/流量表用可用宽度；长篇报告/解释文字限制阅读行宽。不能把“提高密度”理解成正文铺满全屏，也不能让宽屏中央仍是窄手机栏、两侧空置。
- 同一边界用一种分隔方式；不连续套卡片、重复边框、重复标题。主要内容靠减少无效容器和过大间距获得空间，不加无关统计填空。
- 颜色辅助状态，必须同时有文字/图标；普通文字对比度至少4.5:1，大字至少3:1，必要控件/焦点可辨。参考的低对比细节不是必须照抄的缺点。

## 5. 功能与展开态规则（R；每片只覆盖其实际相关状态）

### 执行流与时间线

- 默认先读“发生什么、当前状态、来源/时间”，展开再读参数、输出和证据；保持所属方向与当前选择明确。
- 工具调用与结果按真实身份关联，不能仅因在相邻两行就配对；不同会话/方向同名工具不能串证据。
- “执行成功”“工具返回200”“模型说发现”不等于漏洞确认。候选、独立验证、证据不足及反证分开。
- 阅读历史时不能随新事件强制跳到底；跟随/定位当前步骤应有明确控制。只读展开不能启动、继续或重放任务。
- 选中卡片与卡片内部按钮/摘要是不同操作，键盘能选择、展开、回到触发点；完整状态与焦点不能只验默认首屏。

### 工具、日志与HTTP

- 列表显示必要摘要和状态，原件就近读取；工具输入、执行输出、模型回答不能混成一个无来源文本框。
- 请求与响应各有标题和可独立阅读的正文区；提供原文/格式化/复制等操作时必须有真实能力，不能因为参考图有按钮就造空按钮。
- 原件、格式化视图和预览分开。重建头、截断、无响应、捕获失败及发送未知都如实显示，不能把展示层拼接声称为线上逐字节原报文。
- 参数/长日志的滚动留在内容区，不让工具栏和主要操作消失；只在有真实需求时支持调整分隔比例。
- 精确原件应按任务与证据显式读取；复用组件不等于接受固定上游全局自动同步全部Artifact的行为。

### 发现、报告和复测

- 漏洞主文维持“简短描述／复现步骤／修复建议”；真实请求/响应就近关联。过程、版本与复测历史按需查看。
- 报告目录与正文联动、长文有限行宽；生成、发布、导出、外部投递是不同动作，不能相互冒充。
- 每个漏洞独立复测保留新证据与历次报告；目标不可达/登录失败不能显示为已修复。
- 以上多项尚未接入新原生业务底座；规范先明确效果，不开放占位导航、不生成假报告填版面。

### 表单、面板与反馈

- 简单表单用有界居中Dialog，正文内滚动、标题和主操作可达；需要并行对照的证据可用非遮挡详情面板，不一律做巨大抽屉。
- 保存与连通测试分开，查看/保存不能隐式触发计费探测；API key用密码字段，已保存秘密不回显，其他字段更新不强迫重填。
- 错误在触发处说明；加载、空数据、失败、禁用、成功不是同一个空白面板。只读权限不允许人为制造参考站失败或执行状态来凑矩阵。
- 处理Tab/Escape、焦点归还、遮罩层级、窄屏滚动和长字段；几何无溢出只是一个检查，不替代看图与操作。

**方法：** 先核现有原生对象与事件 → 找可复用组件 → 仅补业务授权/证据/成果缺口 → 调整展示组合。不能从页面看起来相似推断它具有同样的授权、持久化或恢复保证。

## 7. 后续每个功能任务包必须包含

1. **用户路径**：从哪个入口，选哪个对象，到哪个可读/可操作结果。
2. **参考依据**：V/O/S编号和准确状态；未观察项标U，不能把计划或按钮点击记录当成功。
3. **布局对照**：主要区域、相对比例、导航/工具栏位置、文本层级、行宽、滚动归属；沿用什么、必要偏离什么及原因。
4. **真实能力**：底层数据/原件/状态来自哪里，当前未实现项不露假入口。
5. **受影响状态**：默认、选中、展开/收起、相关页签/面板、长内容、必要异常与键盘；不为每个小改动跑全系统矩阵。
6. **验收证据**：真实交互、同viewport前后图、DOM几何与必要可访问性检查。技术通过、主视觉复核、用户认可分列。
7. **交付**：原生源码覆盖及清单可追溯；前端仍由每轮新可见`wangsu-ds-pro-latest`实施。轮末预览遵守当前资源保护/明确重启许可，不能借验收绕过保护。

重大布局偏离先说明；已确定的共同规则不每轮重新发明。新增功能有新参考时增补这一份规范与状态矩阵，不复制出相互冲突的“规范V2/V3”。
