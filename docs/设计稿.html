会员中心 API · GET /api/orders/{id} · 越权读取他人订单

新发现 修复中 逾期 3 天 · VULN-0123 · 首次发现 2026-11-12 10:24
一句话影响 提炼漏洞最直接的业务或数据影响，便于研究员与研发快速判断危害

普通用户可通过修改路径中的订单 ID，越权读取任意其他用户的完整订单详情，响应体直接返回收件人手机号、姓名与详细收货地址。

前置条件： 需要任意普通登录用户账号（复现使用普通测试账号 user_b，无管理员权限）。
正常对照 越权类漏洞必选：展示同一身份访问本人资源与越权访问他人资源的响应差异

修复建议

  • 服务端归属校验：查询订单前校验 order.user_id === session.user_id，不匹配返回 403 Forbidden。
  • 防止 ID 遍历：对外暴露的订单编号改用不可预测的随机串或签名 ID，避免纯自增数字。
  • 补充鉴权单测：在订单接口集成测试中增加跨账号读取（BOLA/IDOR）回归用例。

复测方法

使用普通用户 user_b 的有效 Token 重放步骤 2 请求（GET /api/orders/90018274），期望服务端返回 HTTP 403 且响应体不含他人订单信息。
