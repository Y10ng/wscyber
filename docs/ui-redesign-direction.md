# 当前界面整改方向：优秀实际设计优先

## 1. 优先级调整

用户认为当前布局简陋，缺乏逻辑、实用性、可读性与美观，不像成熟完整系统；明确允许在开发过程中自行学习优秀项目并改进组件和布局，不局限旧约束。

因此：

1. **先学习Cyber、ARTEX等优秀项目的实际工作流、信息组织和展示效果。** 不是只借字号/颜色，也不是按数据库字段排页面。
2. **再决定适合本项目真实能力的布局与交互。** 记录具体参考、沿用点、未观察范围和必要差异，不凭空自创后以测试背书。
3. **组件库/UI-1服务于设计，不反过来限制设计。** 合适的复用，不合适的改造或替换组合；允许对外壳、导航、分区、内容宽度、排版、密度、主题层级作有依据的改进，再统一沉淀回共享库和用例。
4. **用真实可操作页面及时展示。** 不再花整轮只做不接业务的大模板，不以几张压力测试长文截图替代产品体验；实现、技术验证、展示、用户认可分开记录。

用户已经授权上述自主学习与UI改进，不再逐项重复笼统开工确认。重大产品范围、后端授权、数据外发、部署或新增依赖仍遵守对应边界；视觉调整不是这些事项的授权。

## 2. 本轮真正要解决的问题

- 任务、方向、候选、验证、证据之间缺少清楚的对象关系和导航，用户难以判断自己在哪里、下一步做什么。
- 多段正文、折叠区、控制按钮、状态、来源连续堆在一条长页，主次关系不清，结果和操作常在页面下方。
- 宽屏一块大容器和横跨整屏的文字，不等于有效利用空间；窄屏简单堆叠也不等于好用。
- 刷新/返回/暂停等操作分散或重复，默认组件的排列没有形成成熟应用的工作方式。
- 过度围绕内部结构、固定像素和“已有组件怎么用”组织页面，忽略实际阅读与操作效率。

这些是已观察问题，不预先等同于某个固定双栏/三栏答案。先对照成熟参考，选择符合真实工作流的组织方式；不把这轮变成另一套无依据的自由拼装。

## 3. 首个整改切片

围绕已有真实任务，打通清楚的阅读/操作路径：**找到任务和方向 → 理解进展与发现 → 定位候选 → 查看结论/独立验证 → 就近查证据或执行必要操作 → 返回原上下文。**

优先重构任务工作台、候选详情与验证展示的整体组织，允许必要的共享外壳与视觉层级改进；其他受影响消费者同时回归。保留已实现模型配置、资料、流量、候选与验证逻辑，不重写后端引擎或擅自改状态语义。

TI-1方向执行流、TI-2任务聊天仍仅待设计；报告/复测/图谱等没有真实能力就不加假入口。可以考虑将来扩展，但不能用预留按钮冒充现成功能。

## 4. 参考与复用的可核验要求

当前证据入口见[界面参考](ui-reference.md)。ARTEX发布图分别展示全局发现列表、任务内会话/方向与主工作区，部分内容是demo；固定源码可补充流程，但都不能说成亲自运行并验收该产品。Cyber已有有限只读观察，未成功观察详情的部分继续明确未知，不重复猜路由或绕登录。

每次改造至少记录：参考片段、对应用户动作、采用的信息组织、实际能力产生的差异、现有组件保留/改造项。允许学习其他优秀项目补足缺口；不复制品牌、应用代码或整段提示词，许可证与外部访问边界不变。

共享实现仍应统一、可复用和可测试；“可改造”不等于各页面私造一份主题或业务状态机。旧UI-1像素、组件形态和布局规定降为历史实现起点；与当前整改冲突时按本文件和用户最新反馈执行，不以旧样式断言阻止合理重构。行为安全断言不能一起删除。

## 5. 不放松的边界与验收

- 授权、证据原件、候选/确认、执行状态/模型判读、原文开关、share=false、未知不重放等语义保持。
- 写入失联只核对原键、401遮蔽、迟到/错归属拒显、草稿和阅读位置、焦点/键盘/减少动效等保护随新布局落实，不绑定必须使用某个旧抽屉或折叠形状。
- 中文简洁、主次清楚、关键内容和操作可读；不靠小字/低对比隐藏信息，不堆开发说明墙，也不删除真实前提或限制来装简洁。
- 展示同时覆盖有意义的正常任务内容与真实多状态，压力长文/异常放独立验证。每个预览明确本机fixture，不在产品里硬编码展示成功。
- 评价顺序包含：对象关系是否清楚、常用路径是否直接、主次操作是否易找、证据是否就近、正常阅读是否舒服、宽窄屏是否合理；然后核对类型/测试/构建和异常保护。无横溢出或符合某个字号不是设计验收本身。
- 旧用户窗口、草稿、预览及失败现场保持；新设计单独展示，不强刷。当前若有服务退出，明确真实健康及未查明原因，不以新端口成功掩盖，也不把视觉改善当可靠性问题已解决。
