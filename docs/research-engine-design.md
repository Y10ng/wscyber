# 漏洞挖掘引擎：稳定优先、模型自主探索

日期：2026-11-11；版本 E1。**稳定优先、不强制全覆盖的方向已由用户明确；具体实现方案仍待评审，未实现或进行效果评测。** E1替代E0的强制覆盖/深度账本和收尾门槛，不将它们继续作为首版前置。

## 1. 当前决定与真实状态

用户明确要求：以稳定运行为主，不必严格覆盖全部，保留关键必须阶段；学习ARTEX，让模型自主选择覆盖与探索，不用协议强制逐项完成。

据此收敛为：**主研究Agent理解目标并自主探索 → 有候选时按需独立验证 → 保存成果和未完成事项；复测另开独立任务。** 规划与探索先在同一主研究上下文中完成；使用同一运行时/工具执行基础，不建设常驻协调器、覆盖审计Agent或多层专家体系。默认串行执行，确有价值且相互独立时才考虑有限分工；这一实施默认值是建议，不是当前代码变化。

当前代码仍是Go/PG薄循环与可靠启动。`internal/research/engine.go` 的 `delegate` 创建 `auto_run=false` 的方向；`internal/model/model.go` 仍发送系统提示词和完整方向Snapshot。独立验证/复测、逐轮模型原文记录及读取接口仍未实现。

无法给出将产生多少报错或故障率：扩展引擎没有运行样本。E0增加了覆盖字段、依赖、分支和恢复组合，存在额外实现/维护成本，但不能把潜在故障点数当实际故障次数。减少不必要机制是降低复杂度，不是稳定性已经验证。

本轮只修改设计，不启动业务开发、付费模型或外部目标测试。新增请求风险控制/审批与外部平台真实对接延期，已有授权/G0保护及未知效果不自动重放不变。

## 3. 保留的关键阶段，不强制固定流水线

| 阶段/职责 | 做什么 | 不要求什么 |
|---|---|---|
| 目标理解与自主探索 | 主研究Agent根据目标、身份、已有证据规划下一步；边理解边测试，重要结果及时保存 | 不要求先完成系统模型表、不固定侦察轮数、不按漏洞类型逐项过关 |
| 候选验证 | 候选若要标为已确认，进入独立验证上下文；核对复现、正常权限/功能和实际影响，保留反证 | 不要求每次探索都经过验证Agent；不靠多个模型投票；无法验证可留待验证，不阻塞整个任务结束 |
| 成果收尾 | 整理实际发现、证据、简短复现/修复建议及已知限制；已有材料可直接生成报告 | 不要求覆盖达到阈值、不为未测项自动无限补测、不让报告阶段重做目标探索 |
| 复测（单独触发） | 针对选定漏洞原版本/复现逻辑，用当前有效身份与环境保存新证据和结论 | 不是每次挖掘必经阶段，不覆盖原发现，不将登录失败或不可达判成修复 |

理解、探索、验证可以往返；没有候选就不启动验证。独立上下文不等于另一个服务/常驻进程，也不要求另一家模型。首版可以用同一执行器依次执行不同任务模式。

**运行中增量交付（用户已确认）：** 发现不等研究结束才统一产生。形成候选后及时持久保存并展示，后续证据、内容与验证状态随进展更新；候选可见不等于漏洞已确认。探索尚在运行时，用户即可查看已保存的发现、关联流量与当前验证结论；新增反证或修订保留历史。成果收尾只做汇总与固定版本整理，不作为发现保存、验证结果展示的门槛；默认串行执行也不意味着延迟到任务结束才展示。

### 模型自行决定

- 先查看什么入口、如何理解业务、哪些风险值得测试。
- 是否继续追踪某个线索、换方法、暂缓或结束。
- 根据已保存的结果调整计划，优先有价值线索，避免重复劳动。
- 必要时提出有限子任务；首版不依赖自动多Agent扇出才能工作。

提示词保留简短研究准则：真实证据优先、正常行为对照、尝试反证、考虑权限与业务逻辑、记下未决线索、零发现也可正常结束。这些是研究指导，不转成每步必须满足的复杂JSON表格。

## 4. 删除或降级E0中的复杂要求

首版不建设：

- 业务/身份/状态/风险的强制覆盖矩阵及多维版本状态机。
- 每个接口必须达到指定深度的程序关卡。
- 必须先生成完整SystemModel、CoverageItem、Hypothesis等一套新领域对象才能探索。
- 常驻覆盖审计Agent、自动缺口补测闭环、结束前覆盖率门禁。
- 固定专家树、递归分派、复杂任务优先级评分或跨Agent消息总线。

简单计划、已尝试方法和未决线索可优先利用现有Thread/Observation/Event记录。需要时提供方法清单供模型参考；不要求填满，不因缺一项而报错或拒绝收尾。不展示虚构覆盖百分比，也不将运行结束宣称为系统完全安全。

目标流量与证据仍为必需；用户最新将模型逐轮原文记录改为可开关，开启时保存并提供受控读取，关闭时保留研究事实与最小运行元数据、不旁路保存原文。这些不是覆盖强制协议。**流量捕获是否完整与漏洞测试是否覆盖全部是不同问题**：未采集/截断仍须明确，不能借放宽探索覆盖而静默丢失记录。

用户已接受身份/业务规则、上下文选择、有限工作区、持久增量展示与有界恢复的补齐方向，要求先寻找优秀组件学习/复用。新增资料库保存 skill，选定版本按需装配；新增可开关的禁止行为提示词，与后续流量审批统一归入测试安全。关闭附加提示词不扩大授权或绕过现有程序保护；导入 skill 不自动执行附件。详细配置、开关与失败语义见[研究配置补充](research-configuration.md)，具体默认值/组件/契约仍待冻结。

## 5. 程序只守住必要运行边界

| 必要边界 | 为什么保留 |
|---|---|
| 明确授权、已有origin/DNS/G0保护、项目归属 | 自主探索不能变成任意目标访问；延期风险模块不等于移除已有保护 |
| 时间/步骤/资源上限与暂停 | 防止模型或工具一直运行；不要求用尽预算，不因分工重置预算 |
| 工具输入基本格式与返回状态 | 工具必须能调用、错误必须能解释；不检查研究清单是否完整 |
| 实际动作/证据/最小运行事实持久保存，模型原文按开关保存 | 失败后知道做过什么；关闭原文记录时不承诺完整还原模型交互 |
| 已发送效果未知不自动重放 | 避免为了恢复任务再次产生副作用 |
| 候选、已确认、严重度、复测结论分开 | 保住成果可信度，不把正常功能/低危/无法验证混为一谈 |

最小字段限于运行必需的任务/归属、状态、工具参数、结果与证据引用；不为所有自然语言研究想法建新协议。精简字段不等于移除现有可靠提交、解析校验和凭据保护。

## 6. 容错重点：错误发生后仍然可控

错误可分为模型/网络失败、工具执行失败、材料不足、持久化/恢复失败和业务结果不确定；这不是故障频率预测。设计重点不是承诺零报错，而是不要让可处理的局部失败拖垮整个研究或形成错误结论。

- 模型超时/限流/格式错误：保存调用及失败状态；只有明确未触发目标动作且适合重试的调用才可做有界退避重试，达到上限后暂停/阻塞，不无限修复JSON。不能为补日志重复发送效果未知的动作。
- 单次工具失败/工具缺失：保存真实错误，模型可换方法或跳过，失败不自动等于整个系统研究失败；同类错误重复出现时停止空转。
- 身份失效/材料不足：保留该方向或候选的未决状态；无依赖工作可以继续，没有可行下一步就收尾并说明限制。
- 数据库不可用/结果无法可靠保存：停止新派发，避免边执行边丢记录。恢复后先读持久事实，不把工具成功但写回失败当成未执行。
- 重启/取消/暂停：已保存事实不丢弃；可能已发送的动作保持未知待核对，已生成的报告不因重试导出而重做研究。
- 报告整理失败：保留发现和证据，只重试整理/导出，不重新测试目标。

当前并非已经实现上述全部容错。重试分类、上限和恢复状态只在实际开工时冻结最小必要契约，不预建通用工作流平台。

## 7. 收尾由研究判断与资源边界决定

主研究Agent认为本轮没有值得继续的线索时可以结束，并简要说明结果与已知限制；预算结束、人工暂停、前提不足或不可恢复错误也能明确收尾。不要求覆盖率、最低深度评分或审计Agent批准。

候选未完成验证可以保留待验证，不为了让任务结束而强行确认/否认。没有漏洞是合法结果，任务结束不表示系统安全；不用大篇覆盖报告或常驻警告打扰用户，但不能把已知没测的地方写成已测。

## 8. 验证顺序：先稳定，再逐步改善挖掘效果

先做一个小型端到端纵切，不等大型评测平台建完才运行：

1. **正常运行**：受控系统上完成探索、真实证据保存、候选验证、报告；无候选也可收尾。
2. **必要故障用例**：模型超时/无效输出、工具失败/缺失、数据库写回失败、暂停/重启、目标效果未知；检查有界结束、材料保留与不重复副作用。
3. **基本质量用例**：正常权限功能不误报；真实低危不当误报；证据不足不确认；复测登录失效不判修复。
4. **小规模效果对照**：获准后在同模型/工具/总预算条件下重复测试少量有真值的业务场景，观察有效发现、误报、耗时、token和重复劳动。

工程fixture可用确定性模型，真实挖掘效果必须用相应获准的真实模型与受控目标，二者分开报告。优先修复阻塞/丢证据/重复执行等稳定性问题；只有实际样例反复暴露漏项或调度不足，才考虑补一个有明确收益的机制。覆盖矩阵/多Agent对照不再是首版强制前置，不能因为担心偶尔漏测重新塞回E0全部设计。

## 9. 下一步与停止边界

稳定优先和自主覆盖方向已确认；建议实施形态为同一Go/PG执行基础上的主研究模式、按需独立验证/复测模式与本地报告。先明确这几个关键模式的最小输入/输出、失败处理与证据关联，再交用户确认具体开工切片。

产品范围及模型记录接口建议见 [product-confirmation](product-confirmation.md)。本次只收束文档，不批准新框架、固定Agent数量、业务开发、真实模型测试或部署。
