# 界面规范

前端由 `wangsu-glm-latest` 实现，主会话在浏览器亲自操作验收。规则优先级：用户最新要求 → 业务真实性 → 本文 → 现有代码。

## 1. 目标

**界面像 Cyber 参考图：布局排版、区域比例、导航位置、主次层级、信息密度都要对齐，不是在旧布局上换皮。** 每个功能都要对齐到展开后的效果（详情、弹窗、页签、原文、请求/响应、加载/空/错误态），不能只看默认首屏。

产品重点是：Agent 执行输出、日志、工具结果、HTTP 数据包、漏洞与报告。这些要好读好查，而不是视觉炫技。

## 3. 用户原始设计要求（原文要点）

- 先理解功能、任务、使用频率，再决定布局；不按代码或接口顺序排版。常用操作好找，低频适度收纳。工具页面按工具设计，不做营销首页。
- **严格控制辅助文字**：不给每个标题/卡片/输入框加说明；不用大量浅灰小字制造层次。保留必要的字段标签、单位、错误和风险提示。
- **布局有主次**：核心内容占主要空间；不用“统计卡片 + 卡片网格”模板；按内容选列表、表格、分栏、详情面板；避免卡片套卡片和重复边框。
- **视觉克制统一**：少量字号/间距/圆角/颜色；正文可读，不靠缩小字号塞内容；颜色用于操作、状态和层级；无渐变发光厚阴影。
- **交互真实**：加载/空/错误/成功/禁用都处理但不堆文案；明确可点击、选中、悬停、焦点；响应式不是简单缩小；用真实长内容和多条记录检查。

## 4. 页面骨架

| 阅读任务 | 骨架 |
|---|---|
| 找任务 | 标题/搜索/主操作 → 状态筛选 → 行列表 → 分页 |
| 看探索进展 | 方向/会话选择 → 执行流或时间线 → 就地展开参数/输出/证据 |
| 查工具调用 | 过滤栏 → 调用表 → 所选调用参数与结果 |
| 查 HTTP | 记录列表 → 同一记录的请求/响应双栏 → 来源与捕获状态 |
| 看候选/验证 | 宽屏：任务导航 + 候选列表 + 详情（正文限宽，原件区可展宽）；窄屏：列表/详情切换 |
| 读报告 | 目录 + 有限行宽正文 + 就近证据 + 独立导出 |
| 配置 | 有界居中 Dialog；保存与测试连接分开 |

任务上下文栏：返回、任务名、真实状态、必要元信息同行，视图切换与任务级操作在此。

## 5. 细则

- 列表/流量表用满可用宽度；长正文限制行宽。宽屏两侧不留大片空白，也不把正文横跨整屏。
- 工具调用与结果按真实 call ID 配对，不按相邻行猜。阅读历史时新事件不强制滚到底。
- 请求与响应各自可读、可复制；原件、格式化、预览分开；截断/重建/无响应如实标出。只读展开不触发执行。
- 状态色必须配文字；普通文字对比度 ≥ 4.5:1。
- 键盘：Tab/Escape、焦点归还、Dialog 遮罩层级正确。
- 字号尺度已在 2026-11-14 做过一次约 10% 调整，以后不再累计放大。

## 6. 验收

浏览器实际操作该功能的用户链，桌面（约 1440 与 2000+ CSS 宽）和窄屏（约 520 / 390）各看一次，包括展开态；与参考图对照。可用 Playwright 截图/DOM 尺寸、axe 检查辅助发现问题，但工具通过不等于设计合格，最终靠主看图判断。
