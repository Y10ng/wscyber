## 2. 待设计功能 TI-1：每个意图／研究方向的运行交互记录

### 用户终点

打开一个方向，能看懂“系统给这个方向下发了什么任务、现在做到哪里、调用了什么、返回了什么、为何暂停或失败、形成了哪些证据/候选”。这是面向研究过程的执行流，不是只展示后端服务日志或一张模型调用统计表。

### 建议内容层次

1. **方向任务说明**：方向目标、来源、系统实际下发的执行要求及后续调整记录；按当时下发内容保存，不用现有可变Thread标题/下一步回填历史。不将派生摘要标成实际下发提示词。
2. **逐次尝试的执行流**：按真实Attempt组织模型调用、已公开返回的决策/说明、Skill活动、工具输入与结果、观察/证据、候选新增/更新、等待/暂停/失败。日志关联到同一事实来源，不让模型事后编造事件或因果关系。
3. **按需查看实际模型输入/返回**：复用B组调用记录、原文读取和C3-A装配来源，显示对应call、记录状态、脱敏/截断及未读范围。任务说明、装配元数据和真实发送输入分别标识；已装配、已尝试发送、发送未知、完成不能合称“模型已执行/采纳”。
4. **就地查证**：工具输入/输出成组；HTTP继续使用已有请求/响应检查器，命令结果仅显示实际捕获的stdout/stderr/退出状态。点击日志或复制内容不重新执行请求。
5. **持续查看**：持久历史＋有界增量读取，方向筛选、加载较早记录、底部跟随/上翻停留、新消息提示、断线恢复去重；切任务和401取消迟到读取。选择SSE还是既有增量/轮询机制时先核对服务能力，不在本轮定新消息中台。

### 原文开关不能被绕过

- 既有“模型原文记录”默认关闭、固定到任务的语义保持；关闭时仍能看有限业务事实、方向说明和状态，但不通过执行日志旁路保存完整system/user/provider返回。
- 希望查看每轮实际完整提示词时，需要对应调用当时已开启记录且有保存内容；老调用未记录就显示“未记录”，不根据现在的模板反推，也不自动发起模型调用补造。
- 方向任务说明的独立快照属于建议新增的有限业务记录，字段、容量、敏感处理和保存时点待冻结；不得把全部研究上下文伪装成方向说明。现有Thread可变字段不是不可变下发记录。
- 不承诺获取供应商未提供的内部推理；展示实际可提供且按策略保存的消息、工具活动、简短决策说明及结果，不制造“思考过程”。

### 已有底座与缺口

可复用`Thread/Attempt/Action/Observation/Event`、B组`ModelCall/ModelCallContent`、C3-A装配来源和S1活动；D组候选关联仍需完成当前首片复核。现有Event不足以直接充当完整Transcript：统一稳定顺序、跨类型来源关联、不可变方向下发快照、有界分页和持续展示仍需设计，不能仅按时间拼接就假称有完整执行链。

## 3. 待设计功能 TI-2：每个任务内的对话助手

### 用户终点

在任务里直接询问“现在进展怎样”“这个方向为何停下”“已有候选依据是什么”，也可以表达“优先关注某个接口”“这个方向先暂停”“补充一个业务前提”。对话始终绑定当前任务，可引用某个方向、调用、证据或候选；不是无上下文的通用聊天框。

### 查询与调整分开

| 用户意图 | 建议行为 | 不能做 |
|---|---|---|
| 询问状态、解释已有结果 | 读取有界、带时间/来源的真实任务事实后回答；能定位到对应记录 | 为回答状态问题启动目标测试、改优先级、恢复任务；把候选称为已确认 |
| 讨论/建议一个方向 | 给出建议，保持尚未变更的状态 | 将“你觉得要不要……”当作执行授权 |
| 明确要求调整方向、补材料 | 明确影响哪个方向、形成什么实际指令/材料，调用受控业务操作并反馈持久回执和生效时点 | 模型仅说“已调整”就当保存成功；把普通补充文本冒充调度优先级已修改 |
| 明确暂停或接续 | 复用相应可靠控制语义；暂停派发与停止当前对话生成分别处理 | 假称暂停会撤销在途请求，或提问/加提示后静默恢复暂停任务 |
| 范围不明、越界或重大改变 | 先澄清具体分歧；新增授权走正式范围流程 | 用聊天文字扩大allowed_origins、预算、凭据分享或绕过现有保护 |

明确且在授权内的用户调整不必机械再弹一次确认；只在歧义、重大影响或需要额外授权时确认。不能把任务对话变成逐步探索审批。

### 真实性与控制建议

- 显示“消息已保存／调整待应用／后续尝试已携带／操作失败或待核对”等真实阶段；模型是否理解/遵从不由保存或装配自动证明。对已发出的调用不回写历史，不假称指令立即生效。
- 优先在下一安全调度/上下文装配边界应用；更强的实时中断/在途调整需要单独能力验证。方向优先级、新增方向等写契约目前未冻结，不能仅接现有补材料入口就宣称全部支持。
- 对话消息、服务端操作和执行回执分别持久化并关联；同一消息/操作有幂等身份，失联只核对，不自动重复调用供应商或执行目标动作。对话不会成为第二套调度状态权威。
- 对话使用当前任务已绑定且可用的模型作为优先建议，不另行静默换供应商。模型对话会消耗调用额度，计入同一账本但区分用途；现有研究每Attempt最多一次调用的约束不因新增聊天而改变。具体调用身份/预算/并发和恢复需另冻契约。
- 状态问答默认只拿必要元数据和已获准分享的材料，不能因为“问状态”就外发全部任务原文。继续遵守share=false、秘密隔离、任务归属与不可信目标内容边界；跨任务消息/来源不得混用。
- 任务暂停/结束后仍可查询历史，不因发送一条查询自动重启研究。聊天“停止回答”与研究“暂停探索”是不同操作。
