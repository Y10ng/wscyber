日期：2026-11-11；版本：D1 + UI-1（compact设计已认可，具体业务契约按轮冻结）。

**本文件组织产品范围，不是已批准的全量开发规格。** 用户已明确认可compact模板，要求固定[UI-1规范](ui-baseline.md)、新开主会话逐轮开发；后续功能允许按需求调整布局。不必重复等待模板认可；未定重大业务契约、切换服务、真实目标/产品模型/外部平台仍需相应确认。第7节为历史布局建议，以UI-1覆盖；模板批准、业务契约、具体开发片与生产部署不可混为一谈。

## 1. 如何阅读与确认

- **已确认**：用户已明确提出的产品要求或约束。
- **现有实现**：已有代码及实际验证支持的能力，不代表最终设计获得认可。
- **建议，待确认**：本稿给出的流程、布局、执行角色和工程取舍。
- **待外部材料**：没有真实协议/格式/授权就不能定案或实施。
- **后续**：保留产品方向，不纳入第一版完整交付要求。

冲突处理：本稿组织本轮评审，不静默覆盖既有已确认要求。事实以 [STATUS](STATUS.md)、[API](api.md) 和代码为准；目标详见 [vision](vision.md)、[architecture](architecture.md)、[frontend-design](frontend-design.md)、[findings-and-reporting](findings-and-reporting.md)。本稿中的新对象/状态/路由是建议，不是已支持 API。

**D1最新补充（2026-11-11）：** 用户接受架构补齐方向并强调先找优秀组件复用/学习；目标请求/响应记录为必需，逐轮模型实际输入/返回记录改为可开关，开启时提供受控读取。新增文件夹式 skill 资料库及运行时选用，新增可开关的禁止行为提示词，后者与未来流量审批统一归入“测试安全”。完整新增请求审批与外部平台实际对接仍延期。关闭提示词限制不扩大授权或关闭现有程序保护；资料库不自动执行脚本。详见[研究配置补充](research-configuration.md)，其开关语义覆盖此前模型原文必记要求；具体默认值/组件/契约及模板仍待冻结。独立验证/复测复用同一执行基础，不因此批准固定多层拓扑。

**当前引擎方向：** 用户明确稳定运行为主，保留关键阶段，让模型自主覆盖/探索，不以协议强制覆盖完整或深度达标。按[研究引擎E1](research-engine-design.md)收敛为主研究Agent自主探索、候选按需独立验证、成果收尾，复测另行触发；不建设强制覆盖账本/专门覆盖审计/复杂专家树。最小工具格式、授权、预算、证据/模型记录、失败恢复仍保留。该方向已明确，具体实现与开工切片待评审；下文批次不自动启动，界面模板不等于引擎方案获批。

## 2. 已确认的产品目标

独立、自托管的授权安全研究平台。首版聚焦 **Web/API 漏洞挖掘**；不把代码审计、CTF、内部攻防演练同时铺开。核心路径是：明确目标与授权 → 自主研究 → 保存流量与证据 → 形成并验证候选漏洞 → 简洁交付 → 新一轮复测。外部平台对接后续再做。

已确认要求：

1. 创建入口两个主要输入：目标／已知信息、希望达到的目标；明确可执行范围后开始，不要求用户手工拆方向。
2. 自主选择研究步骤，不审批每次推理或每个工具调用。**新增请求风险控制与审批首版暂不要求**；长期保留针对实际请求的风险处理方向，不因此移除现有origin/DNS校验、G0保护或自动放行历史pending。
3. 类Burp目标流量记录与请求/响应查看、复制；不据此自动承诺Repeater、扫描器或全协议代理。
4. 探索图谱，以及逐漏洞的发现时间线；有结构化来源，不以模型生成故事代替事实。
5. 漏洞正文只有简洁描述（原理/危害）、复现步骤、修复建议；步骤就近关联并复制真实流量。
6. 稳定漏洞编号；证据、验证状态、报告版本相互可追溯。验证关注真实性、实际危害与正常权限/功能误报，严重度与是否成立分别记录。**运行过程中即可持续看到新增发现及其更新，不等任务结束统一整理后才展示。** 候选持久保存后即可见，明确待验证状态；后续证据、正文与验证结论按进展更新并保留历史。成果收尾只汇总已有材料，不是首次创建或展示发现的前置条件。
7. 每个漏洞可复测，保存每次独立报告。外部复测任务接入和结果投递保留长期方向，**首版不要求实际对接**。
8. 模型实际输入/返回记录可开关；开启时保存每轮实际内容并提供受控读取，关闭时不保存原文但保留研究事实和最小运行元数据。目标流量仍必须记录，不受此开关影响；不等于批准外发。
9. React/TypeScript + 官方Ant Design；桌面实际最大化窗口优先、美观、正文14px与紧凑间距、精简常驻文案；最新参考要求见 [界面参考](ui-reference.md)。
10. 先共同明确需求、架构、组件和布局，查看模板后再统一组织分模块并行；优先寻找优秀轮子学习/复用，核验适配、许可证和恢复语义后采用。
11. 文件夹式资料库可存放 skill，用户可在运行时选择携带；固定所选版本、按需加载，不因资料导入自动执行脚本或扩大授权。
12. 禁止行为通过可开关的提示词清单配置，测试环境可关闭附加约束；与未来实际流量审批同属“测试安全”，但提示词软约束不等于强制拦截，现有授权/程序保护保持。

13. **后续核心需求（2026-11-11）：** 全局 Agent 模型配置，支持不限于 GPT/OpenAI、Anthropic 的多供应商/多模型、自定义接口地址/Header/请求参数及显式连通性测试。记录实际 tokens 和计费信息，仪表盘查看每日及每个任务用量。尚未实现，不插入当前 TF-1；费用估算与供应商账单分开，原文关闭仍统计 usage。具体设计边界见[模型配置与用量](model-configuration-and-usage.md)。

## 5. 核心用户流程与异常路径

### J1 创建与研究

选择/新建项目 → 两个主要输入 → 检查明确授权 → 可选身份/高级限制 → 开始探索 → 启动已接收 → 查看实时方向与证据。

- 提交未知先查操作回执，404只表示尚未查到；显式重试沿用原键原内容。
- 模型未配置、身份失效或预算不可用：说明阻塞点，不生成虚假运行状态。
- 补充材料是新增带来源的观察，不覆盖原证据或默默扩大授权。
- 暂停表示阻止后续派发，不谎称在途请求被撤回；接续先消费已保存材料。

### J2 目标流量与模型记录

从项目/方向/漏洞步骤进入流量中心 → 选择目标流量或模型调用 → 查看同一来源对象的实际记录 → 按需复制/读取。

- 目标流量：请求、响应、捕获来源/限制和发送结果；复制不发请求。未发送/无响应不能拼造目标HTTP响应。
- 模型调用：轮次、用途、模型、状态、耗时；实际输入/返回按需展开，不把整个聊天记录常驻研究工作面。
- 秘密默认遮蔽，受控原件访问与普通预览分开；关闭详情后恢复遮蔽。
- 目标效果未知保留核对材料、不自动重发；浏览器提交未知与目标效果未知不同。
- 首版模板不以待放行/审批操作为主流程；现有G0待审只按真实阻塞兼容，不因延期而自动放行。

### J3 候选漏洞、独立验证与报告（执行方案建议）

研究证据 → 候选记录/稳定编号 → 独立验证任务 → 支持/反证与判定 → 三段式详情/发现时间线 → 固定版本生成报告草稿 → 审阅/导出。

建议验证Agent使用新的执行上下文，领取候选主张、原始证据、复现前提及明确授权；原研究结论只作待检验主张，不作权威答案。可共用同一个模型适配器/调度器，不要求独立进程、另一家模型或常驻专家层。

验证至少核对：

1. 按有效身份、环境、前提能否复现；必要时在授权内取得新证据，不只让另一个模型阅读结论后投票。
2. 预期权限/业务规则是什么，实际行为是否违反。管理员正常操作、本人访问本人数据、产品有意开放的能力，不能仅凭请求成功当作漏洞。规则未知时保留不确定性。
3. 有何可证明的越权、数据暴露、完整性或可用性影响；支持/反证及未验证边界分别保存，不为证明危害实施越权或破坏性验证。
4. **是否成立、严重度、报告纳入策略分开。** 真实低危问题仍可成立；低价值/提示性观察可分类或过滤，不标成误报，也不夸大成高危。

模型给出结构化建议，程序校验必需证据/引用/前提与允许的状态转换；独立Agent不是正确性保证。证据冲突、关键业务权限未知或无法安全验证时保留证据不足，必要时交人工复核，而非强行二选一。

修改证据/发现后生成新revision或新报告，不替换历史依据。报告生成、发布、远端接收是不同状态；首版只做本地交付。

### J4 独立复测与报告（执行方案建议）

漏洞详情 → 固定原Finding revision、原复现逻辑及成功判据 → 核对本次目标/环境/授权/身份 → 创建独立复测任务 → 执行并保存新证据 → 本次结论与独立报告。

- 复测Agent可复用验证执行器，但任务目的不同：验证原问题现在是否仍存在，不另起一次无限探索。
- 沿用逻辑不等于字节级重放：登录态、CSRF、动态对象ID等按本次有效环境更新，记录变化；核心条件无法等价满足则无法判定。
- 先检验有效登录、目标可达、正常功能对照等前提，再判断原越权/影响是否被阻断。不可达、登录失败、材料不足或单纯未复现，不自动标已修复。
- 结论区分：仍可复现、此次范围内修复已验证、无法判定。部分影响面仍存在或未覆盖要明确，不以一个失败请求声称全面修复。
- 新证据不覆盖原发现；新问题另建候选记录。外部任务接入/结果投递延期，不纳入此流程验收。

## 6. 核心架构建议（待确认，不新增代码）

### 6.1 技术与职责

保留 **Go模块化单体 + PostgreSQL权威状态 + React/Ant Design工作台**。不因页面变多拆微服务，不先引入消息中台/图数据库，不用Agent框架替代业务事务。

| 模块 | 唯一职责 | 不应承担 |
|---|---|---|
| API/业务控制 | 鉴权、范围/归属、提交幂等、状态转换、人工操作、受控读取 | 在创建handler直接调用模型/目标 |
| 研究调度 | 有限决策、探索/验证/复测任务隔离与按需分工、预算与证据交回 | 自行扩大授权或把Agent意见当真实证据 |
| 工具执行/目标流量 | 有界任务、取消/超时事实、结构化结果、实际目标请求捕获与来源 | 冒称全工具覆盖、以采集成功证明请求安全 |
| 模型适配/调用记录 | 实际发送/返回边界采集、版本与关联、失败事实 | 只存摘要或事后重构提示词、保存供应商鉴权密钥 |
| 证据与来源关系 | 原件/引用/捕获限制/版本/归属 | 摘要替代原件、图谱成为第二事实库 |
| 发现/验证/复测 | 编号、修订、支持/反证、独立任务与结论 | 把模型文字/HTTP200/退出0自动视为确认 |
| 本地报告 | 固定输入版本、生成/校验/导出 | 生成即发布、导出即外发 |
| 后续风险/外部适配 | 请求策略/人工决定、外部协议/交付回执 | 成为首版流量/验证/复测的强制前置 |

组件状态：Go/PG/官方模型SDK/React/antd已使用；研究框架Eino/ADK、代理/MITM、图形库、PDF组件只是候选。先保留薄循环；仅当受控实验显示明确收益才替换。选型核验许可证、固定版本、运行依赖与恢复边界，参见 [components](components.md)。

### 6.2 领域对象与关系

- Mission：目标与业务范围。Scope版本与Identity引用是拟扩展；不把背景文本当授权。
- Thread：长寿命问题；Attempt：一次有限执行尝试。探索/验证/复测共享底层调度但使用独立任务上下文，不把Attempt编号当作全局LLM轮次。
- ToolAction：一次工具任务；OutboundRequest：实际目标请求，二者一对多。当前Action不等于已实现独立请求模型。
- ModelCall：一次实际模型调用，关联项目、方向、尝试、用途、逻辑轮次和重试关系；一次研究轮次可有多次调用，一次调用可提出多项工具动作，不能强制一一对应。
- Observation：有来源的观察；Evidence：原件/元数据/捕获限制。初期优先现有PG和版本化引用，不预设新存储服务。
- Finding + revision：稳定身份与内容版本；Verification：独立验证材料/判定；Retest：绑定原版本的新验证任务。
- ReportVersion：固定发现/证据快照的派生物。PolicyDecision/Release、Delivery/外部映射保留后续边界，不要求首版建全表。
- 来源边与事件：图谱和时间线的读取依据。一个证据可支持多个发现，一个发现可关联多条请求；模型调用与目标流量是不同事实，按实际活动/证据引用关联，不凭时间接近猜测因果。

**授权与恢复不变量：** 跨项目不串材料；原始证据不改写；已发送效果未知不自动重放；预算不因接续/派生清零；硬拒绝不能人工越权；外部平台不是本地事实权威。

### 6.3 状态必须分开

| 状态维度 | 用户需要区分的事实（概念示例，非冻结枚举） |
|---|---|
| 提交 | 尚未发送、提交中、结果待核对、已接收 |
| 研究/执行 | 排队、运行、暂停、阻塞、结束、失败；保留现有G0等待兼容 |
| 请求发送/结果 | 未发送、发送中、已有响应、发送效果未知 |
| 模型调用 | 已准备、调用中、已返回、错误、中断/结果未知；另记捕获与解析状态 |
| 漏洞验证 | 候选、待验证、已确认、证据不足、不成立 |
| 严重度/报告选择 | 严重度及依据、是否纳入报告；低危不改变成立事实 |
| 处置/修复 | 未处理、声称已修复、风险接受等；不覆盖验证状态 |
| 复测结论 | 仍可复现、此次范围内修复已验证、无法判定 |
| 本地报告 | 生成中、草稿、生成失败、发布版本 |
| 后续策略/交付 | 自动允许/待人工决定/拒绝/人工已放行；投递/送达/失败/回执未知 |

界面可以汇总展示，但不可在持久层把这些维度合并为单一status。确切枚举/迁移在契约阶段冻结。

### 6.4 可选模型逐轮记录与读取契约建议

**开关优先语义：** 以下原文采集、输入先持久化及原件读取要求仅适用于开启记录的调用。关闭时不保存原始输入/返回，也不从日志/追踪旁路留存；仍保存被采纳的研究决策、动作、证据、最小调用状态/预算元数据。关闭不阻塞研究或目标流量采集，原文读取明确“未启用记录”；切换不补录过去、不自动删除历史。建议按任务启动固定配置，默认关闭仅为建议。开启后记录失败才适用本节停止调用/未知恢复要求。详细边界及资料库、测试安全见[研究配置补充](research-configuration.md)。

**记录位置与内容（开启时）：** 在模型适配器真正发送/接收的边界采集，覆盖探索、验证、复测及后续报告等所有实际模型调用。保存最终组装的system/developer/user/assistant/tool消息（协议支持时）、本次实际工具定义、模型/参数/模板版本，以及实际返回正文、工具调用、拒绝/终止原因和供应商返回的usage。不能只存用户输入、解析后的Decision或可变模板引用；不存在的usage记未知，不估造成实数。只记录模型实际返回的内容，不承诺获取未返回的内部推理。

建议元数据包括：稳定call ID、mission/thread/attempt/task关联、用途、逻辑轮次、父调用/重试关联、请求/返回时间与耗时、供应商/模型标识、捕获状态、错误类型、解析结果和原件引用。平台HTTP目标流量与模型供应商通信分别分类，不把LLM请求混成漏洞目标请求。

**失败与完整性：** 发送前持久化输入及调用意图；若记录失败，不静默启动没有记录的调用。返回后先保存实际结果，再解析/消费。超时、取消、无效JSON、拒绝、长度终止、可获得的部分响应都保留真实记录，不因解析失败抹除。当崩溃发生在发送/返回/落盘之间时标记未完成或结果未知，不能承诺完整记录供应商已处理但平台未收到的内容，也不为补日志盲重放。以后若支持流式，需记录中断/捕获边界与可获得片段；每次实际重试分别记录，不覆盖前次。

**建议读取能力（路径待冻结，不是现有API）：**

- `GET /api/model-calls`：按项目/方向/用途等过滤，游标分页，默认仅脱敏元数据。
- `GET /api/model-calls/{id}`：详情及输入/输出原件引用，明确捕获/解析状态。
- `GET /api/model-calls/{id}/input`、`.../output`：经权限校验读取相应内容，普通脱敏视图与受控原件明确区分，列表不内嵌大量敏感正文。
- `GET /api/model-call-events?cursor=...`：供未来增量采集的变更流，包含调用开始/完成/失败等持久事件。不能只按创建时间递增拉取，否则会漏掉已列出调用的后续返回。

采集按稳定事件ID去重，游标只前进至可安全消费的已提交事件边界，不以数据库预分配序号假定提交有序；允许重读、不承诺恰好一次。无访问权限不返回正文；跨项目归属检查沿用业务边界。保留周期、删除/墓碑、游标过期及大记录读取上限在实现前冻结，过期明确要求重新同步，不能静默跳过。

**敏感材料：** 模型供应商API key及传输鉴权头不纳入业务交互原件。输入/输出本身可能包含目标Cookie、Token、个人数据或内部代码：原件按敏感证据受控保存，普通列表/日志/预览不泄漏，脱敏视图不覆盖原件。具体原件权限、加密/密钥生命周期和留存政策在契约阶段确定，不因首版单管理员就公开原件。未来采集平台所需读取身份和允许传输字段单独授权；本轮只设计本地读取，不实现外部推送/连接器。

## 7. 界面模板范围与布局建议

### 7.1 统一外壳

- 官方Ant Design统一浅暗主题；正式左侧导航按最新基线208px/折叠64px，顶部保留项目上下文和简洁操作，不做大面积营销页或统计看板。模板旧224px是历史建议，不约束正式工作面。
- 全局导航建议更新为：**项目、流量、资料库、设置**。项目内部页签：**研究、流量、漏洞、报告**；复测从漏洞详情进入，并可在报告区查看其报告。创建页高级区域提供资料选择、模型原文记录开关和测试安全设置；保持两个主要输入不变。测试安全首版展示禁止行为提示词开关/清单，未来请求审批归于同一板块，不提供未实现的审批操作。
- 流量中心分为**目标流量 / 模型调用**；同一导航容纳两种记录，但独立列表/字段/详情。模型输入输出按需展开，不做常驻全量聊天工作台。
- 全局与项目流量复用列表/详情，仅作用域不同；跨项目查看显式显示项目，跳转不丢范围。
- 按实际最大化浏览器可用宽度组织内容，不再统一限制1200px窄列；创建Modal按表单需要限宽，研究/流量利用剩余工作区。记录真实窗口与viewport，另验1440×900和1920×1080浅暗，390px保基本可操作。
- 2026-11-11最新反馈覆盖旧16px底线：正文/表格/表单统一14px，标题16/20/22px；减少纵向留白，短状态/时间/操作同排。参考 [UI规范](ui-baseline.md)，不以旧模板尺寸限制正式界面。

模板可以切页、选行、开详情、切状态；模拟状态改变或生成内容明确为“演示”，仅内存操作，无API、数据库、执行器、真实模型或外部目标。刷新重置；不保存敏感数据。原始演示报文、脱敏预览与复制区分；复制不发网络请求。

图谱仅用少量演示关系验证布局和跳转，附等价关系表及文字标签；不因模板锁定生产组件。没有假发现数量/完成率/成本看板。

## 9. 已获准逐轮开发，按需冻结小片（不同时启动全路线）

1. compact设计已获认可；用户补充要求实际组件库覆盖规划所需组件，按UI-1先建设共享组件、可点击展示页和覆盖矩阵，再接入已有正式React行为；允许后续功能调整布局，不迁入fixture。
2. 主会话按一个小轮次冻结domain/API/状态/错误/迁移/归属契约，不要求一次定完所有记录对象；目标流量与模型记录基础随后按依赖实施。需工具采集实验时另行明确授权范围。
3. 每批主会话+最多两个额外短会话，优先一个，公共文件单一负责人，执行会话不再委派；前端按复杂度使用已有GPT，主/执行均可见交互，交回后停止。
4. 单元/接口测试后，用真实隔离后端与可见浏览器验证同一流程；模板不是验收替代品。

| 批次 | 先完成的共享契约 | 可并行部分 | 交回门槛 |
|---|---|---|---|
| B1 事实/记录基础 | Request/ModelCall/调用事件、Evidence引用；任务配置包含资料版本、禁止行为与模型记录开关；先核验复用组件 | 后端必需目标流量/可选模型原文、受控读取；前端研究/记录组件 | 模型原文开关两条路径可运行，关闭无旁路存原文；目标流量保留，未知不重放，增量不漏事件 |
