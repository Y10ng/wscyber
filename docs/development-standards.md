# 当前开发规范总览

更新：2026-11-13。**用户已明确否定当前布局，并授权自主学习优秀项目、改进布局与组件，不受旧组件库/UI-1约束。** 当前优先级见[界面整改方向](ui-redesign-direction.md)：实际工作流与设计质量优先，组件随之演进；业务真实性/授权/恢复边界不变。下文旧像素起点不能盖过最新用户反馈，也不以工程检查代替设计认可。

**当前授权：2026-11-12用户已明确恢复开发，要求正确快速完成完整系统，不只停留在最小契约。按[首版完整系统交付](system-delivery.md)持续实现、联调和验收；不重新使用历史撤销任务。以下前端规则是开发规范的一部分，不代替全系统架构、接口、数据、运行与交付要求。**

## 1. 前端究竟按什么做

| 层次 | 权威来源 | 作用与限制 |
|---|---|---|
| 设计优先级 | 最新用户反馈与[当前整改方向](ui-redesign-direction.md) | 现布局被否定，优先逻辑/实用/可读/美观；允许自主学习和必要整体重构，不用旧模板认可限制改进 |
| 产品功能/流程参考 | Cyber与ARTEX优先，必要时其他成熟产品；[参考证据](ui-reference.md) | 先看实际工作流、对象关系、展示与操作；区分页面观察/发布图/源码核对，不把未知说成已参考 |
| 本项目组件实现与用例 | `web/src/ui/`、`web/src/component-preview/`、[组件清单](ui-components.md)、历史[UI-1](ui-baseline.md) | 作为可演进资产：保留合适的、改造不合适的，再统一沉淀；不能以旧组件形状限制合理设计 |
| 底层控件依赖 | 已锁定的React/TypeScript、官方Ant Design | 提供控件实现/API，不是完整应用设计；不为样式问题无依据换技术栈 |
| 业务真实性 | `internal/domain`、[API](api.md)、[STATUS](STATUS.md) | 决定真正能做什么；不能把后台字段直接搬成用户流程，也不能用模板假功能补齐页面 |

**不是按Ant默认控件或旧组件形状拼页面，而是先学习成熟应用设计，再用可演进的共享实现落地。**

## 2. 组件库已经有什么、还缺什么

以下为源码/文档核对，不是本轮重新运行的视觉验收。

### 已有共享实现

- `UIProvider.tsx`、`surface.ts`、共享样式：单一浅暗主题、字号、颜色、间距及portal样式。
- `AppShell.tsx`：左导航、顶栏、折叠与主内容区。
- `TaskModal.tsx`：居中任务弹窗、视口内布局、键盘焦点补偿；业务草稿与提交由调用层持有。
- `SurfaceControls.tsx`、`clipboard.ts`：复制反馈、Grid折叠、短新增文字等交互原语。
- `EvidenceBytesViewer.tsx`、`evidenceBytes.ts`：已保存字节查看、预览复制、原字节下载。
- `component-preview`：基础控件、表单、数据列表、弹层、反馈及证据用例；覆盖矩阵为六类41项。

**41项是规划覆盖条目，不是41个全部完成的共享业务组件。** 矩阵明确区分“可复用／仅展示／待补／本期不适用”。完整研究工作面、流量组合、资料选择、发现/复测等仍有仅展示或待补项；模型配置键值编辑组合也没有在当前矩阵中被独立列为已完成共享组件。

模板内的资料v1/v2、配置版本、模拟状态等不因模板曾被认可就自动成为正式产品交互。已被用户否定的设计不能继续照搬。

## 3. 先参考设计，再演进共享实现

1. 先明确用户工作路径，实际核对成熟项目如何组织对象、内容与操作，记录参考映射/未知/必要差异；不只从内部API或既有组件反推页面。
2. 再查共享清单/源码/用例，列保留、改造、缺口。合适的直接复用；现有组合不适合新设计时应改造，不能用“库里只有这个”阻止重构。
3. 在统一Provider下使用合适的官方基础控件，不机械包壳；允许对共享外壳、排版、表面与组合作有依据的整体改进。改进统一沉淀，不在每页复制多份主题或相同组件。
4. 共享组合与真实用例随设计实现更新，回归受影响消费者；不为证明补库而另花一轮只造不接业务模板，也不把临时拼装留作正式长期实现。
5. 用户已授权自主学习与UI改进，包括旧UI-1不能容纳的合理布局。普通视觉/交互改进不反复问开工；新的产品能力、后端语义、数据/部署授权、依赖选型仍按相应规则确认或核验。
6. 共享组件不混入演示业务状态机、鉴权、目标访问或模型调用；可靠提交、取消/迟到、归属和真实接口留在业务层，不因重构丢失。

## 4. 实现起点与必须保留的行为

下表尺寸/样式是旧实现起点，可以按2026-11-13最新授权有依据调整；不是重构的硬上限。授权、秘密、草稿、真实状态与可访问性等行为保护必须保留，并落实到新布局，不机械绑定旧组件形状。

| 项目 | 实现起点／行为要求 |
|---|---|
| 技术栈 | 正式前端React/TypeScript；Vue只保留工程原型身份，不另建第二套正式规范 |
| 主题 | 单入口单UIProvider；颜色和语义字重源于`web/src/ui/surface.ts`，禁止页面私建主题 |
| 字号 | 正文、表格、表单、状态、时间、placeholder、提示和错误统一14px；标题通常16/20/22px |
| 密度 | 紧凑间距，常用4/6/8/12/16px；短状态、时间、操作尽量同排，长内容自然换行 |
| 宽度 | 按实际最大化浏览器可用宽度设计；不靠固定窄视口或无理由max-width留下大面积空位 |
| 导航与控件 | 正式侧栏208px/折叠64px；桌面控件36px/紧凑32px，触屏主要按钮至少40px |
| 任务/配置表单 | 优先复用居中TaskModal；视口内滚动，不另造侧边配置Drawer |
| 证据查阅 | 就地复用检查器，保持来源页签、阅读位置与关闭后焦点；Drawer用于查证，不泛化为所有表单 |
| 文案 | 中文、简洁；不加常驻小字说明/解释段，也不能放大字号或换位置规避 |
| 错误与反馈 | 必填/错误在触发处就近显示；未知状态如实表达，不重复同义成功通知 |
| 草稿与秘密 | 默认只留内存，不进入URL/浏览器持久存储；关闭不无意吞草稿，明确退出按现有契约清理 |
| 键盘与动效 | Tab/Shift+Tab、Escape、来源焦点、减少动效有实际验证；不能只验鼠标点击 |

旧16px和后续14px均有历史背景；当前按最新整改目标选择统一、可读的排版，不把某一旧像素值当成设计验收。compact模板认可不等于后续每一页认可，当前布局已经被用户明确否定。

## 5. 产品交互必须遵守

- 先参考同类用户流程，再组织页面，不按数据库字段或API DTO机械生成表单。
- 配置保存就是更新，不让用户管理内部revision/v1/v2，不提供“保留／替换／清除”秘密操作模式。
- API Key按必填密码字段处理；已有值不回显，修改其他字段不强迫重填。必要内部一致性机制需说明实际用途，不能反过来决定用户流程。
- 保存、测试连接、任务实际使用分别是真实动作，不把其中一个成功冒充其他动作已完成。
- 只开放有真实后端行为的导航和按钮；演示数据不进入正式页面，不伪造发现、费用、进度或成功状态。
- 接口未知、未发送、运行中、失败等状态按事实区分；不靠隐藏状态、自动重放或装饰文案掩盖功能缺口。

## 6. 每个前端任务开始前必须写清

任务包至少包含以下五项，缺项先补设计依据，不先写页面：

1. **用户行为终点**：用户本轮到底能完成什么，不是“加几个组件”。
2. **参考依据**：实际看了哪些同类流程、沿用哪些内容、哪些未观察、必要差异是什么。
3. **组件复用表**：现成组件/用例路径、缺口、补库范围；共享文件有唯一写入负责人。
4. **页面与状态约定**：字段组织、主次操作、加载/空/错误/未知/禁用/长内容；新机制不直接当作已批准规格。
5. **验收与停止点**：真接口与fixture边界、视觉/交互检查、影响哪些共享消费者、未做哪些功能。

不要求每轮重新制定架构和全局设计；在已确认范围内做小片。用户明确暂停、否定方案或要求只整理文档时，自动接续授权立即让位，不继续派发实现。

## 7. 验收不是“能编译就算好”

- **组件层**：新增/变更共享组件有可点击用例与相关状态，回归受影响的正式/设计/展示入口。
- **页面层**：实际最大化窗口、1440/1920及390px基本适配，浅暗、长文本、弹层、焦点、草稿和错误按影响范围验收，实际查看截图。
- **业务层**：正式组件接真实接口或明确标示的隔离fixture；核对真实状态，不以样例成功代替实际提交/持久化。
- **技术层**：类型检查、构建、针对性测试，失败日志保留；未跑不称通过，不默认每轮全仓套餐。
- **交付层**：实现完成、测试通过、已展示、用户认可分别记录。测试不能代替用户对功能设计与视觉质量的判断。

## 8. 开发与授权边界

Go控制面、PostgreSQL权威状态、模块化单体和可替换适配器不变。优先核验成熟组件；新增依赖说明用途/许可证并锁版本。主维护契约/状态/任务归属，最多额外两个可见执行会话，优先少量串行；关键任务使用已有astra，简单非关键使用sol/terra。短轮次不等于反复空交接，也不得关闭用户仍在使用的原入口或预览。

只在本项目工作，不读取/迁入Arena。产品真实模型、外部安全目标、业务库迁移、部署、外部投递和Git提交/推送需各自明确授权。恢复先消费已有材料，效果未知的外部动作不自动重放。
